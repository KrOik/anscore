## 1. 本轮决策

1. **25K 为唯一默认物理验收平台。** 新增 IP 先在 25K 上进行仿真、综合布线、板端受控回放；具备条件再进行实外设持续数据测试。
2. **减少“反复烧录”成本。** 采用可复用的 `capture_replay` / `stream_metrics` / `fault_injector` 测试顶层，通过 JTAG 预置、帧/数据/参数切换和读回完成多轮测试；已接入的 8 通道逻辑分析仪用于补齐 GPIO 端实际时序、握手和协议观测。同一已综合镜像可复测不同数据和参数；**新 RTL 或改变硬件结构仍须重新综合和下载**，不承诺未经实现的动态局部重配置。
3. **20K 现有工程为有效资产，不强制逐一移植。** 根据资产通用性及子系统依赖筛选 25K 复验对象。
4. **不把高资源、大引脚或厂商硬核列作 25K 阶段的必达目标。** DDR3 Frame DMA、PCIe Endpoint/SGDMA、三路物理 RGB888、依赖专用硬件的 MIPI 摄像头系统保留为后续可选产品集成工单。
5. **优先“组合已有核”，再编写缺失组件。** 避免重新实现已有的 25K Stream、CSR、采集、诊断、存储和基本运算核。

### 1.1 25K 硬件事实与设计边界

依据 Sipeed Tang Primer 25K 官方资料：GW5A-25 有 **23,040 LUT4、56 BSRAM（合计 1,008 Kbit，约 126 KiB）、28 个 18×18 乘法器、6 PLL、75 路普通 GPIO**，核心板有 64 Mbit NOR Flash。官方 Dock 可外接 **40Pin SDRAM 模块**；板上没有像 138K Pro 那样的 DDR3。**官方 Dock 不引出 MIPI 高速引脚**；若计划使用 MIPI，需要核对 SOM BTB、专用引脚与另制硬件。

- 640×480×RGB888 **单帧约 900 KiB**（921,600 byte），大于 25K 片上 BSRAM 总量。大帧缓存不是纯片内验证项目；逐行/分块处理可以片内完成。
- 三路并行 RGB888 的数据、PCLK/HS/VS/DE 最小总量约 **84 根信号**，超过 75 路普通 GPIO：25K 只要求验证**多路逻辑流和显示调度**，不要求三路全并行物理接口。
- PCIe、DDR3、AE350 等 **138K 特定能力不纳入 25K DoD**（Definition of Done）。
- 具体 LUT/DSP/BSRAM/IO 占用以实际 Gowin 综合和布局布线报告为准，不事先承诺所有视觉/AI 核同时装载。

官方资料：<https://wiki.sipeed.com/hardware/en/tang/tang-primer-25k/primer-25k.html>；<https://wiki.sipeed.com/>

## 4. 逐单开发内容与验收

### IP-00（P0）资产目录、接口/权属与成熟度台账

**复用依据：** 同名算法在不同工程内不保证是同一 RTL；20K/CNN/wave2 的封装数、模式数不能简单累加。

- **实施：** 建立 `ip_catalog.yaml`；逐核登记 canonical 源码/commit、接口、参数、复位/时钟、厂商原语、第三方许可、版本、仿真、综合、受控板测、全速/外设板测证据。
- **交付：** `IP_INDEX.md`、`ip_catalog.yaml`、各产品线依赖图、发布资格清单。
- **验收：** 能从任意 IP 名称定位唯一代码/构建配置与日志；明确列出 25K 首批四项全速失配、16 系统核的 UART 命令注入障碍；没有把第三方 DVI/厂商 IP 当成自有原创源码。

### IP-01（P0）Stream Fabric 与控制平面

- **复用：** `frame_switch4`、`width_converter`、`packet_async_fifo`、`backpressure_isolator`、`axi_lite_interconnect`、`atomic_config`、`register_snapshot`、`stream_credit32`。
- **补齐：** 统一 `valid/ready/data/keep/last/user` 的时序/背压和错误定义；视频帧头/行尾与通用报文结尾语义分开；增加 8/16/24/32 位数据适配、可组合 CSR、跨时钟流封装和吞吐/停顿/丢失指标。
- **交付：** `stream_fabric/`、`video_stream_contract.md`、`packet_stream_contract.md`、`csr_map.md`、多核 reference design。
- **25K 验收：** 4 路源按不同长度帧汇聚→位宽转换→异步 FIFO→下游随机停顿，连续回放一致；每帧 byte count/CRC/顺序及 SOF/EOL/packet boundary 正确；报告真实 `II`、Fmax、LUT/BSRAM；与已有系统核互通。

### IP-02（P0）缓冲、DMA 与帧调度

- **复用：** `packet_async_fifo`、`trigger_window`、`capture_replay`、`width_converter`、`burst_split4k`、`address_boundary4k`、`stream_metrics`。
- **补齐：** 行缓存、双缓冲 ping-pong、分块搬运、frame descriptor、环形队列、仲裁与监测；抽象 `mem_port`，片内 BSRAM 后端为默认，**可选** 40Pin SDRAM 后端为第二里程碑。
- **交付：** `buffer_dma_25k`、`frame_descriptor`、`mem_port`、BSRAM reference top；存在 SDRAM 模块时另交 SDRAM adapter。
- **25K 验收：** 两个写入来源及两个读取消费者持续交换图块/行数据；跨帧不串数据，CRC 与参考相同；模拟读写竞争与 backpressure，统计带宽/延迟/溢出；有 SDRAM 时另外给出实测 read/write 带宽，**没有外置 SDRAM 不阻塞片内里程碑**。

### IP-03（P0）流式 ISP / Video Processing Pipeline

- **复用：** 现有 BLC、Demosaic、白平衡增益、LSC、CCM、Gamma、Sobel、Gaussian、HE/CLAHE、曝光/对焦统计、CCA 等；仅选择能在实际资源/吞吐约束下集成的模块。
- **补齐：** `RAW / RGB` 数据契约、行窗口、逐拍控制信号、参数原子更新、各级 bypass、延迟对齐、帧间无串扰；优先做 BLC→Demosaic→AWB增益→CCM/Gamma→Sobel/统计的核心链。
- **交付：** `isp_stream_25k`、配置寄存器、Python/C 黄金参考、阶段与全链路误差报告。
- **25K 验收：** 在虚拟 RAW 流下先测连续 `320×240@30`，然后试 `640×480@30` 的可行子链；验证输出尺寸、像素、帧号、SOF/EOL、II、运行时模式切换。**可用实时外部视频源时追加实采验证**；没有输入摄像头不否定流式受控验收。原 20K Canny 32×24 验收不能直接宣称全尺寸持续吞吐。

### IP-04（P0）25K 统一测试底座、8 通道逻辑分析仪与减少烧录次数

- **复用：** 已有 `capture_replay`、`stream_metrics`、`fault_injector`、`march_controller`、`register_snapshot`、`timestamp64`；沿用已成功的板端 JTAG 预置/全时钟回放/读回；**外部 8 通道数字逻辑分析仪已经接入**。
- **补齐（软件/RTL）：** 核选择/配置表、标准 stimulus descriptor、重复数据回放、统计和 CRC、编译配置指纹；新增低开销、可配置的 `logic_probe8` 调试观测模块与 `la_pinmap`；通过 CSR/JTAG 在一份可综合镜像中选择观测组（`probe_page`），不用因改变观察信号重复生成 bitstream。修复既有 UART 命令注入的物理连接另列子任务，不阻塞 JTAG 主验收链。
- **补齐（仪器）：** 为已接入 LA 建立实际 8 通道到 25K GPIO 的一一映射；核实分析仪 8 通道同时使能时的可用采样率、电平兼容性、触发和导出格式；为通用流、UART、SPI/I²C、PWM/QEI 准备**不同的 8 通道探针页**；保存 LA 工程/导出波形、解码日志与对应设计 hash。
- **交付：** `ip_test_shell_25k/`、`logic_probe8.v`（或 SystemVerilog）、`probe_map.yaml`、`LA_TESTPLAN.md`、`replay_runner.py`、`stimulus/`、`golden/`、`validation.json`、真实采集的波形文件及关联说明。
- **25K 验收（两条证据链）：** (A) 单一已烧录镜像完成 ≥3 个不同的 JTAG 数据/参数测试，golden 与读回一致且不重复下载；(B) 逻辑分析仪**同时采集**至少一个 `valid/ready` 停顿恢复、一个真实 UART/SPI/I²C 或 PWM/QEI 协议/时序案例，实际波形与设计约定一致；两链关联同一版本和运行编号。
- **不计为已通过：** 目前“仪器已接入”只说明工具可用，**不等于已完成 LA 采集或任何 IP 的新增板测**。LA 波形不是内部 24/32 位数据正确性的充分证明；golden、CRC 和完整数据读回仍保留。
- **关键约束：** `logic_probe8` 不改变被测功能数据通路；调试输出使用寄存器隔离，记录由此引入的一个或多个观测延迟；测试壳与被测核共享 56 BSRAM，按功能分组装载，不以“全库单镜像”为通过条件。

#### IP-04-LA：8CH 逻辑分析仪接入子单（随 IP-04 派发）

**推荐观测框架**（一组 8 路同时输出，`probe_page` 通过现有 CSR/JTAG 配置；以下 `D0...D7` 为 LA 通道名，**不是** GW5A-25 实际管脚号）：

| 通道 | Page 0：流式 IP 全链路 | Page 1：串行通信 | Page 2：控制/电机 |
|---|---|---|---|
| D0 | `dbg_clk`（真实待测同步时钟，条件允许时） | `SCLK`（SPI 示例） | `pwm_u` |
| D1 | `test_trigger` / case_start | `CS_N` | `pwm_v` |
| D2 | `s_valid` | `MOSI` | `pwm_w` |
| D3 | `s_ready` | `MISO` | `fault_n` |
| D4 | `m_valid` | `tx_event` | `qei_a` |
| D5 | `m_ready` | `rx_event` | `qei_b` |
| D6 | `frame_start` / `tlast` | `transaction_done` | `qei_index` |
| D7 | `fault_or_overflow` | `protocol_error` | `control_update` |

- **通讯页不是统一强制 SPI 接线。** I²C 换为 `SCL/SDA`，UART 换为 `TX/RX`；用空余通道输出起止、超时和错误事件。**无需为了 8 通道凑齐而牺牲实际物理总线信号**。
- **数字探针只记录真实引脚状态。** 内部信号由 FPGA 扇出到 8 根专用调试 GPIO，不能把 CSR 读回字段误当成引脚波形；外设协议如需观测，应优先直接探测真实总线上的引脚。
- **时序捕获边界：** 在不知道实际采样率前，不宣称能无失真观测 25/50 MHz 乃至更高速度的逐周期事件。对高频时序，优先用内部 `timestamp64`/`stream_metrics` 做时序统计；LA 采用设备可支持的降速受控测试，或输出分频/脉冲拉伸的事件。分频/拉伸波形只能说明事件逻辑，**不能替代原始主时钟的全速外部时序证据**。
- **电气检查：** 核对 LA 输入额定电压、25K IO Bank 供电和 GPIO 复用；共地；探头只作为输入，不向 FPGA 引脚施加外部驱动；测试脚避开 JTAG、上电配置、存储/显示已占用脚。必要时使用板级串联电阻与可靠的短地线，但不预设引脚/阻值。
- **触发建议：** Page 0 可触发 `test_trigger↑` 并检查一次 `valid=1, ready=0` 的停顿持续、恢复后 `valid∧ready` 接受拍、帧边界及 `fault=0`；**数据稳定性**由另一个 `probe_page` 导出选定位数据或由 JTAG/内部断言检查；串口则由协议起始事件或 `CS_N↓` 触发；PWM/QEI 优先捕获互补关系、关断响应及相位变化。

**IP-04-LA DoD：** 实际引脚表已核对；运行至少 1 次 8 通道同步采集；导出可重放的原始采样/波形文件、带测量配置的截图及触发条件；选择两类不同负载完成外部时序/协议验证；每份波形对应 `bitstream_sha256`、`probe_page`、工作时钟、分析仪采样率和测试用例；JTAG 读回或 golden 与 LA 结果无冲突。若设备不具备高采样率则诚实按“降速时序观察”验收，不阻塞其余数字功能核上板通过。

### IP-05（P1）INT8 CNN 推理引擎

- **复用：** 20K PE、数据/权重管理、pooling、activation、量化/BN，以及 `ip_series` 的 `int8_mac_array` 等概念与实现；移植到 25K 后单独记录时序与权属。
- **补齐：** 逐层张量布局、权重装载、算子调度、ReLU/池化、最终输出/Top-K、片上分块计算；模型转换工具及测试数据。首版不强依赖外置 DDR。
- **25K 验收：** 至少完成一个明确定义的*完整*小型 INT8 网络（输入→多层→输出），与同量化规则的软件 golden 在约定舍入/饱和规则下逐层比对；报告延迟、吞吐、DSP/LUT/BSRAM 使用和工作频率。CE=1/16 测试不得标注为 CE=1 全速性能。

### IP-06（P1）同步采集 / 数字锁相 DSP

- **复用：** `dds_nco`、`cordic`、`fir16`、`cic_dec8`、`fft64`、`frame_align4`、`timestamp64`、`trigger_window`、`calibration24`。
- **补齐：** DDS 激励/参考相位、ADC 虚拟采样接口、正交乘法、低通/积分降采样、幅相输出、同步标定和失步报警；后续可接 EIT/电子测量模拟板。
- **25K 验收：** ≥4 路已知频率、幅度、相位的合成流同步进入，核对 I/Q、幅值、相位和采样时间戳；输出误差随幅度/频率/相位变化的实测表；无 ADC 实体时标记为“板级受控输入”，不得标为模拟端到端验证。

### IP-07（P1）以太网与 UDP 数据流

- **复用：** 20K `av_phy`、`av_rmii_rx`、`av_udp`、`av_async_fifo`、`BAV` 解包，及 25K 的包缓冲/流控/时间戳逻辑。
- **补齐：** PHY 独立适配层、UDP 应用侧 stream interface、接收/发送错误统计、缓冲/回压、序列号及端到端数据一致性；已有 20K 100Mbps 物理通过记录不是 25K 实 PHY 通过。
- **25K 验收：** 无 PHY 时完成 RMII/UDP 仿真+板级受控重放；具备 25K 连接实际 PHY 的载板后，完成 100Mbps 连续收发、序列/CRC/实际 throughput 报告。千兆 MAC 不设为首轮必需交付。

### IP-08（P1）视频合成、OSD 与多路输出调度

- **复用：** 已有 `frame_switch4`、`atomic_config`、RGB/阈值/Sobel 核、20K HDMI timing 与网络视频解包的思想或可移植源码。
- **补齐：** 多路独立 timing/帧计数、模式路由、双层 OSD、Alpha/色键叠加、图层更新与安全帧边界切换。
- **25K 验收：** 一路物理显示（实际可接显示模块时）展示 OSD/视频动态切换；另外至少两路逻辑显示输出以 CRC/时序监测并行验证独立性。**不要求三路 RGB888 物理同时输出**；额外 SPI 小屏可以作为扩展演示，不作为核心资产成立的依赖。

### IP-09（P2）FOC / 编码器 / PWM / 故障保护

- **复用：** `pid_core`、`qei_dec`、`pwm_gen`、`can_ctrl`、`wdt_win` 等已有核。
- **补齐：** Clarke/Park、SVPWM、死区控制、电流/速度/位置模式和故障停机；若无电机驱动板先使用数值被控对象。
- **25K 验收：** 输入阶跃/扰动和故障注入，验证 PWM 占空与死区、QEI、故障关断延迟和控制误差；实际电机验证是独立升级门槛。

### IP-10（P2）安全完整性与可靠性套件

- **复用：** 20K `aes128`、`sha256`、`crc`、25K `first_fault32`、`march_controller`、`fault_injector`、`sticky_event32`、`packet_async_fifo`。
- **补齐：** 数据面 CRC/散列、版本/配置完整性、超时/错误记录、掉电/错误镜像的系统级恢复策略（如目标硬件支持）。
- **25K 验收：** 标准测试向量、传输单 bit/多 bit 错误、FIFO/存储测试故障及错误路径可重复验证。**CRC 或 AES 单元通过不等于安全启动、抗侧信道或完整加密设备通过**。

### IP-11（保留项）专用硬核和大型系统

以下继续作为将来的集成产品需求维护，**本轮不派发为 25K 上板任务**：

- 138K DDR3 三屏 Frame DMA、3×RGB888 实体输出；
- PCIe Endpoint/SGDMA 与 PC 侧驱动；
- 25K MIPI CSI-2 实相机接入（只有核对专用 MIPI 引脚、载板及接收 IP 后才单独立项）；
- 1080p 复杂全核 ISP、完整大模型 CNN 及任何超出 25K 带宽/BRAM 的系统；
- 完整 ML-KEM/ML-DSA 及未完成的安全评估。

**跨平台规则：** 一项 IP 在 25K 验证通过后，可登记为“可移植候选”；只有在目标大芯片重新完成综合/板测，才登记“目标平台完成”。

IP-00 资产台账 ──────────────┐
                            v
IP-04 测试底座 ───> IP-01 Stream Fabric ───> IP-02 Buffer/DMA ──┐
                                            │                    │

                                            │                    │

                                            ├──> IP-06 锁相 DSP   │

**建议先完成的组合：** `IP-00 + IP-04 + IP-01`。这三项完成后，后续每个算法核可复用同一组接口、诊断和板级验证资产；随后完成 `IP-02 + IP-03` 以形成首个可售能力清晰的实时视觉流水线，再选 `IP-06`（专业仪器）或 `IP-05`（推理）作第二条高附加值产品线。

## 6. 降低烧录/验收成本的工程约束

1. **默认先离线：** 软件黄金参考 + 仿真回归 + 综合/静态时序。通过后再上板，避免把下载当作逻辑调试器。
2. **一个顶层、多个测试用例：** 每个已构建目标支持运行时配置、JTAG 预置、寄存器读回、统计 counters；参数切换不产生新 bitstream。
3. **按资源分组：** 为 ISP / CNN / DSP 等安排不同测试镜像，保证每镜像包含独立检查机制；不得为追求“一次烧录”使 BSRAM 满载或改变真实数据路径。
4. **尽量 SRAM 下载调试：** 需要临时验证时优先采用设备支持的易失配置/下载路径；只有保留永久镜像才写 NOR Flash。是否节省时间以本机下载记录衡量。
5. **区分软件与物理故障：** 25K 既有 UART 命令注入路径受物理连接问题影响，不应因此反复改写已正确的算法核；先以已成功的 JTAG 测试通道为主。
6. **自动生成证据：** 每次回归导出设计 hash、构建版本、实际 Fclk/CE、案例数、字节/帧数、CRC/差异、LUT/FF/DSP/BSRAM、时序结论。
7. **LA 外部观测优先复用：** 在同一测试镜像中用 `probe_page` 选择 8 路调试引脚，保留触发/时序/协议波形与采样率；探针视角不能替代 JTAG 读回和数值 golden。
8. **快调与全速分开：** 低采样率 LA 允许降速/拉伸事件排错，但正式全速性能仍以原始硬件时钟的板端计数、完整性读回及静态时序报告为准。

## 7. 统一验收等级（禁止跨级推断）

| 等级 | 名称 | 需要的证据 |
|---|---|---|
| L0 | RTL 设计态 | SPEC/接口/参数/源码齐备 |
| L1 | 仿真验证 | 独立黄金模型、边界/错误/随机停顿通过 |
| L2 | 25K 编译通过 | Gowin 实际目标器件的综合 + P&R + 约束时序报告 |
| L3 | 25K 受控上板 | 实际 25K SRAM/JTAG 回放与读回一致，真实目标时钟/CE 已标注；声称 GPIO/协议时序的部分附 LA 实测证据 |
| L4 | 实际连续外设 | 连接相机/PHY/屏/ADC/电机等，对指定工作模式的时长、吞吐、错误进行记录 |
| L5 | 可发布 IP | L1–L3 必备；对应应用要求时具备 L4，另有规格书、权属、集成样例、版本与性能报告 |

L4 在没有实体载板时不构成对所有产品的必要条件；但不能以 L3 证据宣传成已通过真实外设的 L4 产品。

**每单最少发布文件：** `rtl/`、`tb/`、`SPEC.md`、`INTEGRATION.md`、`VALIDATION.md`、`PPA_25K.csv`、`LICENSE_DEPENDENCIES.md`、`CHANGELOG.md`、`examples/25k/`。

## 8. 负责人可直接使用的关闭清单

- [ ] 重用存量核已做代码与许可证核对，不存在重复包装为新原创 IP。
- [ ] 参数/数据位宽/复位/CDC/配置更新语义明确。
- [ ] 能在无硬件时运行独立 golden 和自动化仿真测试。
- [ ] 已记录 25K 的 LUT/FF/DSP/BSRAM/PLL/IO、有效时钟与关键时序余量。
- [ ] L3/L4 所宣称的每一级有独立且可复查的板测证据。
- [ ] 涉及外部引脚/协议的验收已记录 8CH LA 的真实 pinmap、电压/采样率能力、触发、波形及对应 bitstream；不将降速捕获充当全速证据。
- [ ] 可在已集成配置上更换测试数据并读取结果，不为同一参数测试重复烧录。
- [ ] 有干净构建与最小接入样例；接口标准与 `IP-01` 一致。
- [ ] 具体输入频率、分辨率/采样率、吞吐/延迟与外设条件可复现。
- [ ] L5 交付拥有清楚的自研范围、第三方依赖与授权范围。

## 9. 第一批分派建议（按资源而非工期）

- **平台/验收负责人：** `IP-00、IP-04（含 IP-04-LA）`（先开工），并主导 `IP-01` 接口标准。
- **数据通路负责人：** `IP-01、IP-02`（紧随测试底座）。
- **视觉负责人：** `IP-03、IP-08`（先小流水真实跑通，不要求三屏或 MIPI）。
- **专业加速负责人：** `IP-06` 或 `IP-05` 选择一条优先；另一条排 P1 队列。
- **通信/控制负责人：** `IP-07、IP-09、IP-10` 根据实际外设与客户场景排期。

**主工单阶段关闭条件：** 25K 平台上至少形成一套满足 L5 发布要求的 **Stream & Test Fabric**，再形成一套有持续输入、实际 PPA 指标的高价值子系统（建议流式 ISP 或同步测量 DSP）；没有强制 138K 综合/烧录的步骤。
