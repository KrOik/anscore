# hll_reg_update

A 32-register HyperLogLog sketch lives in state: register i is state[6*i +: 6]. One accepted beat merges two 32-bit flow hashes, lane 0 from a and lane 1 from b, each enabled by c[0] and c[1]. A lane takes bucket = h[4:0] and the 27-bit tail field = h[31:5]; the rank is the position of the leftmost 1 of that field counted from its top, rho = 27 - msb(field), so rho is 1..27 and never needs a loop over bits. field == 0 is degenerate: no register is written, the degenerate counter advances and fault rises, because a hash whose top 27 bits are all zero means the upstream hash function is broken and the cardinality estimate would be silently biased. The register write is the HLL max merge, so the sketch is order independent; lane 1 is merged after lane 0 and sees lane 0 write when both hit the same bucket. c[31]=1 clears the 32 registers before the beat; the four session accumulators (accepted lanes, degenerate lanes, seeds, register sum) survive a seed because they live above bit 191. After the merge the beat scans all 32 registers and counts the zeroed ones, which is exactly the linear-counting correction a CPU would collect with a loop. result[4:0]=bucket0, result[10:5]=rho0, result[11]=register0 raised, result[12]=lane0 enabled, result[13]=lane0 degenerate, and the same six fields for lane 1 at result[18:14]..[27]; result[28]=restart echo, result[29]=a register was written, result[30]=no lane enabled, result[31]=no register left at zero. aux[5:0]=zero registers after the beat, aux[11:6]=largest register after the beat, aux[22:12]=sum of all registers (11 bits), aux[23]=register written, aux[24]=a lane was enabled, aux[25]=restart echo, aux[26]=degenerate lane this beat, aux[27]=bank full, aux[28]=accepted total nonzero, aux[29]=degenerate total nonzero, aux[30]=seeds nonzero, aux[31]=register sum above 255. Fault rules: an enabled degenerate lane, and c[30:2] non-zero as a malformed beat (result=aux=0, state kept).

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 2. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: One HLL update in software is a hash, a bucket index, a count-leading-zeros primitive and a compare against a register array spread over four cache lines; this merges two hashes into all 32 registers and re-derives the zero count, the maximum rank and the register sum, the three numbers the cardinality estimator needs, in one enabled beat.

Independent integer model: `step("hll_reg_update", a, b, c, state)` in tools/fam_netio.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 123 distinct responses, 15 fault rows.
