# gf256_poly_eval

Horner evaluation of a polynomial over GF(256) (x^8+x^4+x^3+x^2+1 = 0x11D, generator alpha = x) at the point x = alpha^k, four 8-bit coefficients per accepted beat. c[7:0] = k, the discrete logarithm of the evaluation point, and k = 255 is out of range; c[31]=1 restarts the evaluation (accumulator and coefficient count cleared before this beat); c[30:8] must be zero. The coefficients are consumed in Horner order, highest degree next: c0=a[7:0], c1=a[15:8], c2=a[23:16], c3=a[31:24], and each step is p <- mul(p, alpha^k) ^ c_j, with mul taken from one generated 256-word ROM image (word i = (log[i] << 8) | antilog[i], file line 0 = index 0) so a product is log read + one conditional subtract of 255 + antilog read, and a zero accumulator short-circuits to zero because log[0] is undefined. Four steps retire per beat. result[7:0] = p after all four steps, result[15:8] = after three, result[23:16] = after two, result[31:24] = after one (the whole unrolled Horner chain is observable). aux[7:0] = the accumulator as it entered this beat, aux[15:8] = k echoed, aux[16] = restart applied, aux[17] = at least one step multiplied a zero accumulator, aux[18] = a coefficient was folded into the same value the previous beat produced, aux[19] = coefficient count saturated, aux[31:20] = coefficients consumed since the restart (saturating at 2^24-1, which raises fault). State: state[7:0] = running value p, state[31:8] = coefficient count, state[63:32] = the four coefficients of this beat, state[95:64] = the four coefficients of the previous beat, state[127:96] = the accumulator as it entered this beat, state[128] = started latch, state[129] = count-saturation latch, state[255:130] = 0. A malformed beat returns result=aux=0, fault=1 and keeps state.

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 4. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: A GF(256) Horner step in software is a log lookup, a modular add and an antilog lookup per coefficient with a branch on the zero case; here four steps unroll into eight ROM reads off one fabric-LUT image plus two conditional subtracts and retire a whole quartet of coefficients every enabled beat.

Independent integer model: `step("gf256_poly_eval", a, b, c, state)` in tools/fam_fec.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 127 distinct responses, 2 fault rows.
