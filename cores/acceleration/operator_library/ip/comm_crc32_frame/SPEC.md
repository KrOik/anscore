# comm_crc32_frame

Running CRC-32/ISO-HDLC frame checker over up to 32 new payload bits per accepted beat. Byte j of the beat is a[8j+7:8j], byte 0 folds first and every byte enters LSB first, so a beat is exactly transmission order. c[2:0] = payload bytes folded by this beat, 1..4. c[31]=1 loads the register from b[31:0] before folding, so the standard seed 0xFFFFFFFF turns the nine bytes "123456789" into result 0xCBF43926. c[30]=1 closes the frame and tests the published residue: fault=1 unless the raw register equals 0xDEBB20E3, which is what a correct frame folded together with its own four checksum bytes must leave; a closing beat then reloads register 0xFFFFFFFF and byte count 0 so the next beat already belongs to a new frame. c[29:3] must be zero. result[31:0] = the finalized checksum (raw register complemented, the value a transmitter appends). aux[7:0] = payload bytes folded in this frame saturating at 255, aux[10:8] = bytes folded by this beat, aux[11] = seed applied, aux[12] = frame closed, aux[13] = the byte count was already saturated before this beat (a closing beat clears it), aux[31:14] = 0. State: raw register = state[31:0], byte count = state[39:32]. A malformed beat (byte count 0 or above 4, or a set reserved bit) returns result=aux=0, fault=1 and leaves state untouched.

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 4. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: A 32-bit XOR tree folds four bytes every enabled cycle, so a 1500-byte frame is checked in 375 beats, while the bit-serial loop costs eight shifts, eight conditional polynomial XORs and a 4 KiB table lookup per byte.

Independent integer model: `step("comm_crc32_frame", a, b, c, state)` in tools/fam_comm.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 117 distinct responses, 7 fault rows.
