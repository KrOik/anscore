# afifo_gray

Stateful gray-coded FIFO pointer, status and data-order engine with a 16-entry shadow buffer. State: buffer byte k = state[8k +: 8], write pointer = state[132:128], read pointer = state[137:133], depth exponent N = state[140:138], configured = state[141], pushes = state[149:142], pops = state[157:150], overflow attempts = state[161:158], underflow attempts = state[165:162], order mismatches = state[168:166], peak occupancy = state[173:169]. Configure/restart beat (c[31]=1) takes N from c[2:0], which must be 1..4 (depth = 2^N entries), clears the buffer, the pointers and every counter, and commits nothing on a bad N. With c[3]=1 the same beat preloads the write pointer from a[4:0] and the read pointer from b[4:0], each taken modulo 2^(N+1), and refuses the pair when the implied occupancy exceeds the depth. Op beat (c[31]=0): a[0] requests a write, a[1] a read, a[15:8] is the write data, b[7:0] is the byte the external RAM returns for a read, and c[3] enables the data-order check. Empty and full are decided only from the Gray codes of the two pointers, exactly as a two-clock-domain FIFO must: empty when the two Gray codes are equal, full when they differ in exactly the top two pointer bits; no beat ever uses a binary pointer difference for those two flags. A write is accepted unless the FIFO is full, a read unless it is empty; a refused write leaves the write pointer alone and counts an overflow attempt, a refused read leaves the read pointer alone and counts an underflow attempt, and pointers, counters and peak occupancy always reflect the beats that were actually accepted. The popped byte is returned in result[31:24] from the shadow copy, and with c[3]=1 a byte that differs from b[7:0] is an order or corruption error, counted and flagged while the read still advances the pointer because the external memory really did drive it. Fault causes: 1 = op beat before the depth was configured, 2 = write to a full FIFO, 3 = read from an empty FIFO, 4 = shadow byte disagrees with the RAM byte, 5 = N outside 1..4 on a configure beat, 6 = preloaded pointer pair implies an occupancy above the depth. A faulting beat gives result = 0, aux[3:0] = cause and only the counters named above move. Otherwise result: [4:0]=write Gray code before the beat, [9:5]=read Gray code, [10]=empty before, [11]=full before, [16:12]=occupancy before, [21:17]=occupancy after, [22]=write accepted, [23]=read accepted, [31:24]=popped byte (0 with no read). aux: [4:0]=write pointer after, [9:5]=read pointer after, [12:10]=N after, [13]=c[3] check enable, [14]=configure beat, [15]=op beat, [19:16]=overflow attempts, [23:20]=underflow attempts, [28:24]=peak occupancy, [31:29]=order mismatches.

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 16. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: Two pointer Gray encodes, both equality compares and the 16-deep byte read/write/close all fit one enabled beat at II=1, while firmware must sample both pointers non-atomically, mask, XOR and branch, which is exactly how missed-full and missed-empty FIFO lockups ship.

Independent integer model: `step("afifo_gray", a, b, c, state)` in tools/fam_memsys.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 96 distinct responses, 38 fault rows.
