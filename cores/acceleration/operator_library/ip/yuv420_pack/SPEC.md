# yuv420_pack

4:2:2 macropixels in, 4:2:0 samples out, one macropixel (two luma pixels plus its chroma pair) per accepted beat. Input byte order is YUYV: a = (Y0, Cb, Y1, Cr). The block is a fixed 4x4 luma window, so eight beats carry one block and a 32x8 luma frame is exactly 128 beats: 8 blocks wide, 2 block rows. b[0] is the feeder-declared field parity of this row (0 = top row of a row pair, 1 = bottom) and must match the core counter; a mismatch is an odd-field fault (result=aux=0, a restart request is still honoured). b[31:1] and c[30:1] must be zero; c[31] restarts the packer at block (0,0) before this beat. State is the sub-sample accumulator: bits 2:0 = beat index in the block, 6:3 = block column, 9:7 = block row, 17:10 and 25:18 = the pending top-row Cb bytes of macropixel 0/1, 33:26 and 41:34 = the same for Cr, 50:43 = completed frames. On a top row the chroma is stored and result[31:16] reads 0; on a bottom row the quad commits and result[23:16], result[31:24] = (Cb_top + Cb_bot + 1) >> 1, round half up, exactly the MPEG-2 frame coding choice. result[7:0] and result[15:8] are the two luma bytes. aux[2:0] = beat index, aux[3] = row parity, aux[4] = chroma stored, aux[5] = chroma committed, aux[6] = row pair complete, aux[7] = block complete, aux[15:8] = block column, aux[23:16] = block row, aux[24] = frame complete, aux[25] = the average rounded up, aux[26] = the decimated chroma differs from the top row, aux[27] = this beat brought chroma outside 16..240, aux[28] = Y0==Y1, aux[29] = last block row, aux[30] = last block column, aux[31] = the accumulator still holds pending chroma.

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 2. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: Chroma decimation with field tracking is a read-modify-write of a line buffer plus a parity branch per macropixel in firmware; this core carries the whole sub-sample accumulator in registers and commits an averaged 4:2:0 quad every enabled beat at II=1 with the block addressing beside it, never touching a frame buffer.

Independent integer model: `step("yuv420_pack", a, b, c, state)` in tools/fam_video.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 127 distinct responses, 2 fault rows.
