# lvds_scramble20

LVDS deserialiser scrambler: one 21-bit serializer word per accepted beat (a[19:0]=payload, a[20]=the K/control bit, a[31:21] must read zero). The polynomial is the published self-synchronous 1+x^-3+x^-6+x^-16+x^-20, so o_i = a_i ^ o_(i-3) ^ o_(i-6) ^ o_(i-16) ^ o_(i-20) where o is the line stream: with c[0]=0 the core scrambles (o is the word it emits, so the tap reads its own lower bits, which keeps the tree feed-forward) and with c[0]=1 it descrambles (o is the received word a, and the descrambler of a self-synchronous scrambler is the identical tree, which is why one core does both directions). c[1] re-primes the 20-bit register with the all-ones desynchroniser seed and keeps the statistics, c[31] restarts (the seed plus cleared statistics), and a prime or restart beat consumes no payload. Fault (result=aux=0, state kept): a reserved input bit is set, or a payload beat arrives before the engine was ever primed. State: 19:0 the line-stream register (emitted word when scrambling, received word when descrambling), 27:20 words since prime, 35:28 cumulative ones, 43:36 cumulative transitions, 44 primed. result[19:0]=the scrambled or descrambled word, [20]=the control bit passed through unscrambled, [25:21]=ones in the line word, [30:26]=transitions inside the line word, [31]=no transition anywhere in the word or at the word boundary (a run-length risk for the CDR). aux[0]=direction, [1]=primed, [2]=primed this beat, [3]=restarted this beat, [4]=the word is DC imbalanced (ones outside 7..13), [5]=a transition occurred at the word boundary, [13:6]= words since prime, [21:14]=cumulative ones, [29:22]=cumulative transitions, [30]=the register holds the seed, [31]=this word repeats the previous line word (a stalled or locked feeder).

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 1. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: A firmware scrambler is one XOR tree per bit with a shift-register access each bit time, so 20 bits cost 20 instruction cycles and the pattern is data-dependent; this core unrolls all 20 stages combinationally and emits a whole serializer word every enabled beat at II=1, with the running ones, transition and run-length statistics that a CDR bring-up needs coming out of the same cone.

Independent integer model: `step("lvds_scramble20", a, b, c, state)` in tools/fam_video.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 124 distinct responses, 5 fault rows.
