# fifo_wm

Synchronous FIFO occupancy watermark monitor. State: depth D = state[7:0], occupancy = state[15:8], peak occupancy = state[23:16], pushes = state[31:24], pops = state[39:32], overflow attempts = state[43:40], underflow attempts = state[47:44], configured = state[48]. Configure/restart beat (c[31]=1) takes D from c[7:0], refuses D = 0 as cause 4, and clears occupancy, peak and every counter while setting configured. Op beat (c[31]=0): a[1] requests a pop that is applied first (drain-then-fill), a[0] a push; a pop from an empty level is cause 3 and an underflow attempt, a push to a full level (occupancy = D) is cause 2 and an overflow attempt, and a refused move leaves occupancy alone but still counts the attempt, saturating at 15; accepted moves increment the push/pop counters, saturating at 255, and the peak tracks the maximum occupancy. Fault causes: 1 = op beat before configure, 2 = push to a full FIFO, 3 = pop from an empty FIFO, 4 = zero depth on a configure beat; a faulting beat gives result = 0, aux[2:0] = the cause, and only the attempt counter moves. Otherwise result: [7:0]=occupancy before, [15:8]=occupancy after, [16]=empty before, [17]=full before, [18]=almost-empty (occupancy==1) before, [19]=almost-full (occupancy==D-1) before, [20]=at-or-above half before, [21]=push accepted, [22]=pop accepted. aux: [7:0]=D, [15:8]=peak after, [23:16]=pushes after, [31:24]=pops after. All watermark flags use the binary level, never a pointer difference, so this single-clock occupancy monitor is distinct from the gray-coded two-domain afifo status engine.

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 1. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: One enabled beat computes the new level and the full five watermark flags (empty, almost-empty, half, almost-full, full) plus peak tracking in parallel, where firmware must reload a shared counter, mask, compare against several programmable thresholds and branch per sample, which is how watermark race conditions and lost interrupts ship.

Independent integer model: `step("fifo_wm", a, b, c, state)` in tools/fam_memsys.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 116 distinct responses, 9 fault rows.
