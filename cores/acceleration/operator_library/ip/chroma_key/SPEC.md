# chroma_key

Chroma key decision for four pixels per beat against a window held in state. a[8k+:8] = Cb of lane k, b[8k+:8] = Cr of lane k, c is the program/control word. Only compares, subtracts and shifts appear: db=|Cb-Cb_ref| and dr=|Cr-Cr_ref| by compare-then-subtract, and the metric selects d=max(db,dr) (a rectangular box window) or d=db+dr (a diamond window). The hard radius is the tolerance nibble shifted left by 4 codes (by 5 in diamond mode) and the soft band adds the edge nibble (doubled in diamond mode). Control: c[7:0]=key centre Cb, c[15:8]=centre Cr, c[19:16]=tolerance nibble, c[23:20]=soft-edge nibble, c[24]=diamond metric, c[25]=program request (the new window is already in force for this same beat), c[31]=restart to the default window (128,128, tolerance 0, edge 0, box), c[30:26] must read zero. Fault (result=aux=0, state kept): a reserved control bit is set, or a program request anchors the centre outside the studio chroma window 16..240, which keys the whole frame. State: 7:0 centre Cb, 15:8 centre Cr, 19:16 tolerance nibble, 23:20 edge nibble, 24 metric, 31:25 beats since the last program. result[3:0]=keyed mask, [7:4]=hard-keyed (transparent), [11:8]=soft-keyed, [15:12]=kept (opaque), [19:16]=number of keyed lanes, [21:20]=worst class of the beat, [22]=metric in effect, [23]=some lane had db==dr (a spill tie, the classic green-screen ambivalence), [31:24]=largest lane distance. aux[7:0]=Cb centre, aux[15:8]=Cr centre, aux[19:16]=tolerance nibble, aux[23:20]=edge nibble, aux[24]=programmed this beat, aux[25]=restart this beat, aux[26]=any lane keyed, aux[27]=some lane presented chroma outside 16..240, aux[28]=tolerance is zero (nothing but an exact match keys), aux[31:29]=beats since the last program, low 3 bits.

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 4. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: A firmware key pays an absolute difference, two compares and a branch per pixel per channel; this core decides four pixels against a registered window with pure add/compare arithmetic in one enabled beat at II=1, so the key mask for a whole scan line arrives with deterministic per-line latency and a window change costs one beat instead of a re-issue.

Independent integer model: `step("chroma_key", a, b, c, state)` in tools/fam_video.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 126 distinct responses, 3 fault rows.
