# lpm_trie_step

Longest-prefix match over a 16-bit key domain, walked 8 key bits per accepted beat through a heap-indexed binary trie held as a generated 16-slot image (word = (valid<<29)|(plen<<24)|(prefix<<8)|nexthop, prefix left-aligned, file line 0 = slot 0). Beat: b[7:0] = the next 8 key bits, consumed MSB-first; c[31]=1 arms a new lookup (depth 0, key 0, best none, and a[31:16] must then be zero); otherwise the walk continues from state. All 16 slots are compared every beat and only prefixes whose length is already covered by the consumed bits are candidates, so result carries the best match so far: result[7:0]=nexthop, result[12:8]=matched prefix length (0..16), result[13]=hit, result[14]=walk complete (16 bits consumed), result[15]=complete miss, result[23:16]=completed lookups, result[31:24]=lookups that hit (both saturating at 255 and persistent across restarts). aux[16:0] = the heap node index (1<<depth)-1+prefix reached by this beat, aux[17]=complete, aux[18]=hit, aux[28:24]=number of slots that matched, aux[29]=continued-past-complete flag. Ties (two slots with the same length and prefix) resolve to the lower table index. Fault rules: b[31:8] non-zero or (on a restart beat) a[31:16] non-zero is malformed, result=aux=0, state kept; a continue beat after the walk already completed repeats the cached decision with aux[29]=1 and fault=1 and leaves the state untouched.

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 16. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: A software LPM walks a trie one bit per iteration with a branch and a pointer chase per level, or scans a sorted route list; this compares all 16 route slots and priority-picks the longest decidable match in one enabled beat, and keeps the heap node index of the step on aux so the walk needs no node memory at all.

Independent integer model: `step("lpm_trie_step", a, b, c, state)` in tools/fam_netio.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 127 distinct responses, 44 fault rows.
