# countmin_update

Four independent count-min rows updated, queried and scanned in one accepted beat over the 32 8-bit counters held in state: the cell at row j and column v is state[(8*j+v)*8 +: 8], so the whole sketch is the state register and there is no memory round trip. The four keys are the halfwords k0=a[15:0], k1=a[31:16], k2=b[15:0], k3=b[31:16]; the four increments are the nibbles c[3:0], c[7:4], c[11:8], c[15:12]. Lane L hashes twice, h0=((k>>8)^k)&7 and h1=(((k>>12)^(k>>6)^k)&7)|1 (h1 odd, so the four columns h0, h0+h1, h0+2*h1, h0+3*h1 modulo 8 are distinct within one key), and touches one cell per row. c[24]=1 makes the beat a pure query: nothing is written and nothing can saturate. c[31]=1 clears the sketch before the beat runs. The beat does three passes in one evaluation: sixteen saturating read-modify-writes (a counter clamps at 255 instead of wrapping), a per-lane read-back of the four cells with a minimum pick, and a scan of all 32 cells for the largest counter. result[8*L+7 : 8*L] = the count-min estimate of lane L, measured after this beat writes, so it is never below the true frequency. aux[7:0] = cells whose value actually changed (0..16), aux[15:8] = largest counter after the beat, aux[16] = query echo, aux[17] = a counter clamped at 255 this beat, aux[18] = restart echo, aux[26:19] = sum of the increments applied (0..240), aux[27] = some cell now holds 255, aux[30:28] = lanes whose estimate is zero, aux[31] = the beat changed no cell at all. Fault rules: a clamped counter faults because the sketch silently lost data; c[30:25] or c[23:16] non-zero is malformed and gives result=aux=0 with the state kept.

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 4. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: A flow-count sketch in software is four hash lookups and four read-modify-writes per packet plus a second four lookups to query, with a branch on every overflow; this retires all sixteen updates, the four minimum picks and the 32-cell max scan in one enabled beat, and the clamp that loses data raises fault in the same cycle it happens.

Independent integer model: `step("countmin_update", a, b, c, state)` in tools/fam_netio.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 99 distinct responses, 9 fault rows.
