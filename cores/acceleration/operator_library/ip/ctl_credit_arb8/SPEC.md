# ctl_credit_arb8

Eight-port credit-based round-robin arbiter with fairness accounting. state[31:0]=credits, four bits per port (0 to 15, port k at state[4k+3:4k]); state[34:32]=round-robin pointer; state[36+3k+2:36+3k]=port k consecutive pass-over count, 0 to 7. a[7:0]=request vector, a[15:8]=credit deposits (+1 per set bit, saturating at 15), a[23:16]=credit withdrawals (-1 per set bit, floored at 0), a[31:24] ignored. b[7:0]=port enable mask, b[15:8]=starvation threshold T, b[31:16] ignored. c[31]=1 is an arm beat: port k credit becomes c[3k+2:3k], the pointer becomes c[26:24], every pass-over count clears, and no arbitration or ledger movement happens that beat. On any other beat the ledger is applied first (deposit, saturate at 15, then withdraw), a port is eligible when it requests, is enabled and holds a non-zero updated credit, and the grant is the first eligible port scanning upward from the pointer modulo 8, so the grant is exactly one-hot or none. The granted port pays one credit and the pointer becomes grant plus 1 modulo 8. A port that is enabled and requesting but holds zero credit raises f, and the beat still resolves for the other ports. result[7:0]=one-hot grant, result[15:8]=non-zero credit bitmap after the beat, result[23:16]=sum of remaining credits, result[31:24]=number of enabled requesters. aux[2:0]=next pointer, aux[5:3]=granted port index or 7 when none, aux[6]=grant issued, aux[7]=arm beat, aux[15:8]=eligible-but-skipped bitmap, aux[23:16]=starving bitmap (pass-over count non-zero and at least T), aux[24]= credit violation (same as fault), aux[25]=withdrawal against an empty credit, aux[26]=deposit saturated at 15, aux[27]=a pass-over count saturated at 7, aux[31:28]=0. round_robin8 in the sibling library issues one grant from a pointer with no ledger; this couples credits, per-port starvation counters and a re-armable credit program.

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 8. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: Eight ports are credited, scanned, granted, aged and re-armed in one beat with an exact one-hot output, which a software arbiter can only approximate with a variable-latency priority loop.

Independent integer model: `step("ctl_credit_arb8", a, b, c, state)` in tools/fam_control.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 128 distinct responses, 18 fault rows.
