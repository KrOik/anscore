# turbo_alpha_step

Four log-MAP forward state updates for a radix-2 turbo trellis, one whole trellis section per accepted beat. The four survivor metrics are signed 8-bit values at state[31:0] (byte i = the log-likelihood of state i at the previous section); branch metrics for input bit 0 are A0..A3 = a[7:0] a[15:8] a[23:16] a[31:24] and for input bit 1 B0..B3 from b, all signed 8-bit. State i has predecessors p0 = i>>1 (bit 0) and p1 = (i>>1)+2 (bit 1), and the update is the max-log operation cand = alpha[p] + branch_metric, taking the larger of the two candidates and recording which predecessor won. The four results are then window normalised by one parallel tree: if max-min > 64 the whole vector is shifted down by (max-min) - 64, else if max-min > 32 it is shifted down by the minimum, else it is left alone, which keeps the survivors inside the int8 range without a serialise-and-scan loop. Every candidate sum and every normalised value saturates to [-128,127] and each saturation is counted. c[31]=1 restarts the trellis (state cleared before this beat, so every survivor starts at the uninformative 0), c[30]=1 requests the winner metric instead of the survivor, and c[29:0] must be zero. No multiply: eight saturating adders, four comparators, one 4-wide max/min tree and four conditional subtractors. result[8i+7:8i] = survivor of state i after normalisation (c[30]=0) or the winning candidate of state i (c[30]=1). aux[3:0] = survivor predecessor bits (1 = the +2 predecessor won), aux[7:4] = winner predecessor bits from the previous beat, aux[8] = restart applied, aux[9] = first beat since the restart, aux[10] = at least one state tied, aux[11] = the normalisation tree subtracted something, aux[12] = the window exceeded 64, aux[13] = every survivor is negative (max < 0), aux[17:14] = saturation events counted this beat (saturating at 15), aux[23:18] = 0, aux[31:24] = window width (max - min) as an unsigned byte. State: state[31:0] = the four normalised survivors (byte i), state[35:32] = the four predecessor bits, state[39:36] = the four winner bits, state[55:40] = 0, state[87:56] = the four survivors as they entered this beat, state[95:88] = 0, state[111:96] = sections since the last restart (saturating at 65535, which raises fault), state[255:112] = 0. A malformed beat returns result=aux=0, fault=1 and keeps state. Fault = malformed control or a saturated section counter.

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 4. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: A log-MAP state update in software is a branch per predecessor, a running max scan and a second normalisation pass over the state vector; here eight saturating adds, four comparators and the 4-wide window tree retire one trellis section every enabled beat at fixed latency, which is what keeps a turbo decoder inside its interleave-depth budget.

Independent integer model: `step("turbo_alpha_step", a, b, c, state)` in tools/fam_fec.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 127 distinct responses, 2 fault rows.
