# memprot_scrub_cursor_window

Stateful scrub scheduler accounting over a 1024-row address space scanned as 32 windows of 32 rows. State: cursor=state[9:0] (window base row, 32-row aligned), backlog=state[15:10] (queued unserviced rows, saturating at 63), passes=state[23:16] (completed full sweeps), rows detected since the restart =state[47:24], rows serviced since the restart=state[71:48], both saturating at 24'hFFFFFF. Restart beat (c[31]=1) re-initialises the scheduler: cursor = c[9:5]*32, passes = c[23:16], backlog and both totals cleared, and then this beat is processed exactly like a data beat (so its own bitmap is accounted); c[15:8] is ignored on a restart beat because bits 15:8 overlap the window index. Data beat: a[31:0] is the error bitmap of the 32 rows starting at the cursor (row 0 at bit 0), b[5:0] is the rewrite budget in rows for this beat, b[13:8] is the backlog limit in rows, b[31:14] ignored; a data beat reads no c bit except c[31], so c[30:0] is don't care there. Queued rows = backlog + popcount(a); the beat retires min(budget, queued) rows, backlog rows first and then rows of this bitmap in ascending row order, so result is exactly the subset of a rewritten now and a & ~result is the deferred bitmap. New backlog = min(63, queued - retired); the cursor becomes (cursor+32) mod 1024 and a wrap increments the pass counter unless it already reads 255. result[31:0] = immediate-rewrite bitmap. aux[9:0]=cursor after the beat, [15:10]=backlog after the beat, [16]=window wrapped (next beat starts a new pass), [17]=rows of this bitmap were deferred, [18]=restart beat echo, [19]=backlog saturated at 63 this beat, [20]=budget field exceeds 32 rows, [21]=backlog exceeds the limit, [22]=lifetime deficit exceeds the window, [23]=queued rows exceeded the budget, [31:24]=pass counter after the beat. fault = malformed budget (b[5:0] > 32, a window only has 32 rows) OR the resulting backlog exceeds the limit OR (rows detected - rows serviced) exceeds 1024 rows, i.e. errors arrive faster than the scrub window can retire them.

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 32. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: A serial scrub loop must re-read every row and branch on a software counter; this splits the 32-row error bitmap into rewrite-now versus deferred with one priority walk per enabled beat and retires the backlog, pass and lifetime-deficit arithmetic in the same beat.

Independent integer model: `step("memprot_scrub_cursor_window", a, b, c, state)` in tools/fam_memprot.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 128 distinct responses, 24 fault rows.
