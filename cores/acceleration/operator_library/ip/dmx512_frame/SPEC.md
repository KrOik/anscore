# dmx512_frame

DMX512-RDM receiver framing over measured line intervals, one interval per accepted beat. a[15:0]=the interval length in ticks, a[16]=the line level during it (1=high, 0=low), a[31:17] must be zero. b[7:0]=BREAK_MIN, the consecutive low bit-times that promote a low run to a break; it must be 10..255 because a legitimate low run is at most a start bit plus eight data bits. b[15:8]=MAB_MIN, the consecutive high bit-times after a stop bit that close a frame; it must be nonzero. b[31:16] must be zero. c[5:0]=TS so the nominal bit time is two to the TS ticks (TS=5 is the 4.01 us DMX bit in 125 ns ticks), it must be 1..15. c[11:8]=TE: the interval is timing-legal when its length lies within nominal-(nominal>>TE)-1 to nominal+(nominal>>TE)+1, and TE=0 disables the width check. c[29:12] must be zero, c[30]=1 flushes the pending frame on this beat, c[31]=1 clears the frame accumulation, the runs, the bit position and every counter before this beat is processed. A beat with a must-be-zero bit set or an illegal timing configuration is malformed: result=aux=0, fault=1, state kept. Level low: the first low interval at a byte boundary is the start bit, later low intervals set data bit (position-1) of the accumulating byte (UART data is inverted, so a low bit-time carries a 1) and a low interval where the stop bit belongs is a framing violation. A low run reaching BREAK_MIN becomes a break: a frame with bytes pending is committed first, then the slot counter, the frame checksum and the byte accumulator restart and the receiver is armed. Level high: a high interval inside a symbol is a data 0; a high interval at the stop position completes the byte (slot count +1, frame checksum XORed with the byte) unless 512 slots are already full, which is a slot overflow that drops the byte. A high run reaching MAB_MIN at a byte boundary while armed and holding bytes commits the frame. A low run that ends before reaching BREAK_MIN while the receiver is not armed is a framing violation (a data pulse before any break); its partial byte and bit position are discarded. Committing stores the frame byte count and checksum in the last-frame fields, sets frame valid and increments the committed-frame count. Any timing, framing or overflow violation faults. result[7:0]=the byte accumulator, result[16:8]=slot count after the beat, result[17]=a byte was committed, result[18]=a break was detected, result[19]=a frame was committed, result[20]=timing violation, result[21]=framing violation, result[22]=slot overflow, result[23]=restart applied, result[27:24]=the bit position inside the symbol (0=byte boundary, 1..8=data, 9=stop expected), result[28]=armed, result[29]=this beat line level, result[31:30]=0. aux[7:0]=the frame checksum, aux[15:8]=the low run, aux[23:16]=the high run, aux[24]=frame valid, aux[25]=flush requested, aux[27:26]=0, aux[31:28]=timing violation count [3:0]. State: slot count state[8:0], frame checksum state[16:9], armed state[17], low run state[25:18], high run state[33:26], bit position state[37:34], byte accumulator state[45:38], frame valid state[46], last frame checksum state[54:47], last frame byte count state[63:55], saturating timing violation count state[71:64], saturating framing violation count state[79:72], saturating committed frame count state[87:80], saturating beat count state[95:88].

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 1. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: A break, a MAB and all ten bit-times of a DMX symbol are window compares settled on the enabled edge the interval measurement arrives, so the slot counter never drifts the way a bit-banged CPU frame does when an interrupt steals microseconds out of one bit.

Independent integer model: `step("dmx512_frame", a, b, c, state)` in tools/fam_sensing.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 125 distinct responses, 3 fault rows.
