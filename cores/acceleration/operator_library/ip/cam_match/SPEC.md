# cam_match

Six-entry prefix CAM with longest-prefix-match resolution. State: key j = state[(j*16) +: 16], length/valid j = state[(96+j*8) +: 8] with bit 7 valid and bits[4:0] the prefix length, action j = state[(144+j*8) +: 8], configured = state[192], entry count N = state[195:193], inserts = state[203:196], lookups = state[211:204], hits = state[219:212], misses = state[223:220]. Configure/restart beat (c[31]=1) takes N from c[2:0], which must be 1..6 (else cause 4, state untouched); it clears every entry, resets all four counters and sets configured. Insert beat (c[31]=0, c[0]=1): slot = a[2:0] must be < N (else cause 2), key = b[15:0], prefix length = b[20:16] clamped to 16, action = b[28:21], and the slot is marked valid; the insert count is taken. Lookup beat (c[31]=0, c[0]=0): key = a[15:0]; every valid entry below N is compared in parallel, an entry matches when (key XOR entry-key) masked to the top prefix-length bits is zero (a length-0 entry matches every key), the longest match wins and ties go to the lowest index; a hit takes the lookup and hit counters, a miss is cause 5 and takes the lookup and miss counters. Fault causes: 1 = insert or lookup before configure, 2 = insert into a slot at or above N, 4 = N outside 1..6 on configure, 5 = no entry matched; a faulting beat gives result = 0 and aux[3:0] = the cause, and only the counters named above move. Otherwise result: [2:0]=matched or inserted slot (0 on configure), [7:3]=prefix length, [15:8]=action, [16]=beat referenced an entry, [19:17]=N, [20]=configure, [21]=insert, [22]=lookup hit. aux: [7:0]=inserts, [15:8]=lookups, [23:16]=hits, [27:24]=misses, [28]=configured.

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 6. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: Six parallel prefix compares, their programmable masks and the longest-match priority encoder resolve inside one enabled beat at II=1, and the key array infers into block RAM for a deterministic single-cycle LPM that does not grow with table size, whereas a software LPM table is a linear shift-mask-compare loop whose latency scales with the number of prefixes.

Independent integer model: `step("cam_match", a, b, c, state)` in tools/fam_memsys.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 127 distinct responses, 4 fault rows.
