# comm_polar_enc16

Two independent 16-bit polar (Arikan kernel) encodes per accepted beat. Lane 0 reads the input vector u=a[15:0] and the frozen-bit map f=b[15:0]; lane 1 reads a[31:16] and b[31:16]; bit j is input position j. A frozen position must carry 0, so u[j]=1 with f[j]=1 is a freeze conflict: that bit is forced to 0 for the encode, fault=1, and the conflict is reported. The codeword is x[i] = XOR of the surviving input bits j that are bitwise subsets of i (G_16 = F^x4, F=[[1,0],[1,1]]), so output 0 is the identity of input 0, output 15 is the parity of all sixteen inputs, input 0 repeats into every output and G_16 is its own inverse. c[31]=1 applies the 4-bit index bit-reversal to each input vector before the transform, so either the natural or the bit-reversed channel ordering can be fed; the frozen map always refers to the pre-reversal positions. c[30:1] must be zero. result[15:0]=lane 0 codeword, result[31:16]=lane 1 codeword. aux[4:0]=weight of codeword 0, aux[9:5]=weight of codeword 1, aux[14:10]=information positions used by lane 0 (16 minus the frozen count), aux[19:15]=same for lane 1, aux[20]=lane 0 freeze conflict, aux[21]=lane 1 freeze conflict, aux[22]=bit-reversal applied, aux[31:23]=0. A set reserved bit in c is a malformed beat: result=aux=0, fault=1, and nothing is retained because the core is combinational.

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 2. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: A 4-level XOR butterfly encodes two 16-bit polar blocks per enabled beat with the frozen-bit validity check in the same cone; the same kernel needs a 16-step Gray-code loop plus a mask test per block in software.

Independent integer model: `step("comm_polar_enc16", a, b, c, state)` in tools/fam_comm.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 113 distinct responses, 44 fault rows.
