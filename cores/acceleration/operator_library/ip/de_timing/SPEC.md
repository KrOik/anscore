# de_timing

Display-engine timing generator: one pixel clock of the raster is retired per accepted beat, so a line of H_TOTAL clocks takes exactly H_TOTAL beats and a frame takes H_TOTAL*V_TOTAL beats, all counted in fabric. A program beat is c[31]=1 with the totals in a and b and c[30:0]=0: a[9:0]=H_ACTIVE, a[16:10]=H front porch, a[24:17]=H sync width, a[30:25]=H back porch, b[10:0]=V_ACTIVE, b[18:11]=V front porch, b[22:19]=V sync width (lines), b[30:23]=V back porch, b[31]=0; the totals are built with three adds each (no multiply) and the beat plots clock (0,0) of the new frame, clearing the frame counter. A step beat carries the feeder budgets a[9:0]=clocks per line available, b[9:0]=lines per frame available (0 = unbounded), with a[31:10]=b[31:10]=c=0. Fault (result=aux=0, state kept): a reserved field is nonzero, a zero active area or zero sync width was programmed, a total exceeds the 1024-clock raster counter, or a step arrives before the generator was programmed. State: 9:0 x, 19:10 y, 31:20 H_TOTAL, 43:32 V_TOTAL, 53:44 H_ACTIVE, 65:54 hsync start, 77:66 back-porch start, 87:78 V_ACTIVE, 99:88 vsync start, 111:100 V back-porch start, 119:112 completed frames, 120 programmed. result[9:0]=x, [19:10]=y, [20]=data-enable (inside both active windows), [21]=inside the hsync pulse, [22]=inside the vsync pulse, [23]=inside the vertical active window, [25:24]=horizontal phase (0 active, 1 front porch, 2 sync, 3 back porch), [26]=line start, [27]=line end, [28]=frame start, [29]=frame complete, [30]=this beat programmed the generator, [31]=H_TOTAL exceeds the line budget just presented. aux[9:0]=H_TOTAL, [19:10]=V_TOTAL, [20]=vsync rising strobe, [21]=hsync rising strobe, [22]=last active clock of an active line, [23]= V_TOTAL exceeds the frame budget just presented, [31:24]=frames completed.

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 1. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: A timing generator in firmware is a decrementing counter plus three compares and a branch per pixel clock, and its output skew depends on interrupt latency; this core issues de, hsync, vsync, the phase code and the coordinates for one pixel clock every enabled beat at II=1 from one unbroken counter cone, so every line and frame edge is exact and the budget flags prove the feeder can keep up before the first pixel moves.

Independent integer model: `step("de_timing", a, b, c, state)` in tools/fam_video.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 118 distinct responses, 11 fault rows.
