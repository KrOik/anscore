# rgb2yuv709

BT.709 luma plus 4:1:1 site chroma for four packed pixels per beat. Lane packing: pixel k is (a[8k+:8], b[8k+:8], c[8k+:8]) = (R,G,B), so a = the red plane byte for pixels 0..3, b = green, c = blue. Every coefficient is the Q10 fixed point derived from the BT.709-6 chromaticities (Kr=0.2126, Kg=0.7152, Kb=0.0722) and expanded into canonical-signed-digit shifts and adds. result[8k+:8] = Y_k = clamp(round(16 + (187R+629G+63B)/1024), 16, 235). aux[7:0] and aux[15:8] are the 4:1:1 site Cb and Cr, computed from the four-pixel sums with the studio chroma weights (-103,-347,450) and (450,-409,-41) and clamped to 16..240; because the matrix is affine this is exactly the chroma of the four-pixel mean. aux[19:16] = per-lane luma rounded up, aux[23:20] = per-lane clip flags (|Y_k - group luma| >= 8, i.e. shared chroma clipped over luma detail), aux[27:24] = per-lane achromatic (R==G==B), aux[28] = a luma code sits on the 16/235 window edge, aux[29]/aux[30] = site Cb/Cr sits on the 16/240 edge, aux[31] = a gamut clamp bit actually fired. No fault condition: any three 8-bit planes are a legal colour, and over the RGB cube the studio windows are provably never exceeded, so aux[31] is a structural safety net. Stateless.

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 4. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: A scalar colour conversion pays three multiply-accumulates, a rounding add, a clamp and a chroma subsample filter per pixel; this cone converts four pixels and their shared chroma site in one enabled beat at II=1 and hands the rounding, clipping and achromatic status out beside the codes.

Independent integer model: `step("rgb2yuv709", a, b, c, state)` in tools/fam_video.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 125 distinct responses, 0 fault rows.
