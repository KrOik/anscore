# ipv4_hdr_csum

One RFC 1071 internet-checksum beat over four 16-bit header words: w0=a[15:0], w1=a[31:16], w2=b[15:0], w3=b[31:16]. state[17:0] is the running one-complement sum, state[25:18] the folded-word count (saturating at 255) and state[26] the sticky carry-out-misfold flag. c[31]=1 restarts a header (sum and count cleared before this beat, sticky flag cleared), c[30]=1 finalises it (the accumulator is reduced to 16 bits by end-around folding and the stored sum becomes that reduction), c[29]=1 selects verification: the four words include the transmitted checksum and the core reports the raw 16-bit fold instead of its complement. c[29:16] above those three bits, that is c[28:16], must be zero. Non-final beat: result = the 18-bit reduced accumulator. Final beat: result = the 16-bit complement when c[29]=0, and the 16-bit fold itself when c[29]=1; a complete header whose checksum is correct folds to 0xFFFF and its complement is 0. aux[17:0]=the accumulator stored by this beat, aux[18]=carry-out misfold applied this beat, aux[19]=final, aux[20]=check, aux[21]=verification passed, aux[22]=sticky misfold, aux[31:24]=folded-word count after this beat. Fault rules: the raw sum leaving the 18-bit accumulator (total > 0x3FFFF) forces one end-around fold twice and reports fault; a check beat whose fold is not 0xFFFF reports fault; c[28:16] non-zero is malformed and gives result=aux=0 with the state kept.

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 4. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: A CPU sums header words in a carry-flagged loop and folds end-around with another branch per carry; here four words, the carry fold and the final reduction are one enabled beat, and the running sum stays visible on aux so a checker can watch the fold happen.

Independent integer model: `step("ipv4_hdr_csum", a, b, c, state)` in tools/fam_netio.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 97 distinct responses, 19 fault rows.
