# ctl_watchdog_window32

Windowed supervision of four watchdog channels. state[3:0]=armed bitmap, state[7:4]=sticky early violations, state[11:8]=sticky late violations, state[15:12]=sticky strobe-while-disarmed hits, state[16+16k+15:16+16k]=last accepted timestamp of channel k, state[95:80]=latched minimum window, state[111:96]=latched maximum window, state[115:112]=stale beat count saturating at 15, state[119:116]=violation count saturating at 15. a[15:0]=free-running tick timestamp, a[19:16]=channel of a strobe, a[20]=strobe present, a[31:21] ignored. b[15:0]=maximum window bound and c[15:0]=minimum window bound, both latched only by an arm beat; c[31]=1 arms. An arm beat whose minimum exceeds its maximum is a malformed window: f=1, the beat is rejected and state holds. A valid arm beat sets every channel timestamp to the current tick, arms all four channels, clears both sticky maps, the disarmed-hit map, the stale count and the violation count, and consumes any strobe in that beat. On any other beat elapsed = (tick - last) modulo 2^16 for the strobed channel: a strobe on a disarmed channel sets that channel hit bit, a strobe with elapsed below the minimum is an early violation and one above the maximum is a late violation; each of those three raises f, marks its sticky map, disarms that channel until the next arm beat and counts one violation, and each still re-baselines that channel timestamp. An in-window strobe refreshes its channel, clears the stale count and raises no fault. After the strobe a timeout scan flags every still-armed channel whose elapsed against the current tick exceeds the maximum, as a late violation with the same handling. The stale count grows by one on every accepted beat without an in-window refresh. result[3:0]=armed, result[7:4]=early map, result[11:8]=late map, result[15:12]=disarmed-hit map, result[31:16]=tick echo. aux[3:0]=channels that violated this beat, aux[4]= in-window refresh accepted, aux[5]=arm beat, aux[6]=beat rejected, aux[7]=at least one channel armed, aux[11:8]=stale count, aux[15:12]=violation count, aux[27:24]=strobe channel echo, aux[28]=strobe present echo, aux[29]=violation count saturated, other bits 0. fault=first violation of the current window for any channel, and because a violating channel disarms itself one window cannot spam the fault line. first_fault32 and debounce_word in the sibling library latch one word with one run length; this tracks four independent time windows with sticky per-channel history.

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 4. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: Four refresh windows, sticky violation maps and a timeout scan resolve every beat in hard real time, where a polled software watchdog both misses the early edge and drifts with interrupt latency.

Independent integer model: `step("ctl_watchdog_window32", a, b, c, state)` in tools/fam_control.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 127 distinct responses, 90 fault rows.
