# ctl_slew_limiter_s16

Two independent signed 16-bit slew limiters with asymmetric bounds. state[15:0]=lane0 output y0, state[31:16]=lane1 output y1, both two-complement. a[15:0]=lane0 target, a[31:16]=lane1 target. Lane0 rise limit R0=c[13:0] and fall limit F0=c[29:16]; lane1 rise limit R1=b[13:0] and fall limit F1=b[29:16]. All four are unsigned maximum steps per accepted beat; other bits of b and c are ignored except the command bits. c[31]=1 bypasses the limiter, so y:=target this beat with no clip fault. c[30]=1 freezes both outputs at their held values. Otherwise, per lane: if R and F are both zero the limit word is malformed, that lane holds and f=1 while the other lane still updates; else y := y+R when (target-y)>R, y := y-F when (target-y)<-F, otherwise y := target. A clipped lane always faults, and a clipped step never leaves the signed 16 range because the target is inside it. result=updated outputs with lane0 in [15:0]. aux[1:0]=lanes rise-clipped, aux[3:2]=lanes fall-clipped, aux[5:4]=lanes settled exactly on target, aux[6]=bypass applied, aux[7]=freeze applied, aux[9:8]=lanes with a malformed limit word, aux[31:10]=0. hysteresis32 and range_guard32 in the sibling library classify one unsigned word once; this is a per-beat dual-lane rate governor that owns its output state.

See [common interface](../../doc/INTERFACE.md). Latency: 1 enabled edge(s); II=1 when output ready. Independent lanes per accepted beat: 2. Only accepted transactions update state. Reset clears pending output and state, even while CE is zero.

Hardware advantage: Axis commands and drive setpoints must be rate limited every cycle with different up and down bounds; two lanes with their own clip flags land in one beat instead of a branchy clamp routine per axis.

Independent integer model: `step("ctl_slew_limiter_s16", a, b, c, state)` in tools/fam_control.py. Vector rows: 320, of which 128 run on the board. Board-set coverage: 120 distinct responses, 100 fault rows.
