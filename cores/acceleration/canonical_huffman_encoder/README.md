# Atomic framed canonical Huffman byte encoder

`LINT_PASS + UNIT_SIM_PASS + INTEGRATION_CANDIDATE + HW_UNVERIFIED` for the finite configurations below. This package combines the unchanged B31 runtime codebook with a bounded symbol-frame buffer and an MSB-first byte serializer. A frame is completely validated before any byte is released; an invalid symbol discards the buffered frame and consumes its remaining declared input. The existing codebook by itself only returns individual codewords.

The output is a raw canonical-coded byte frame with explicit bit count and zero padding. It is not a JPEG, DEFLATE, PNG or self-describing compressed file. A decoder must know the active code lengths and original symbol count. Frequency-to-length optimization, file headers, byte stuffing and protocol-specific bit reversal are caller responsibilities.

## Parameters and interface

SYMBOLS=1..256, MAX_BITS=1..16, MAX_FRAME=1..1024, TAG_W=1..32. Defaults are256,16,256,8. Unsupported profiles fail elaboration through a named missing module. All indices/counts/codes are exact unsigned integers; there is no fixed point, saturation or approximation. Every source field is stable while its valid is high and ready is low.

All ports share rising-edge `clk`. `rst` is synchronous active high and dominates transfers. It cancels configuration, partial frames, bytes and completion, and resets the reused codebook. Readiness waits for that codebook's SYMBOLS-cycle staging clear. There is no CE or CDC. A completed reset invalidates all previous code lengths; configure and BUILD again before encoding nonempty frames. Payload code/length arrays are not reset because every successful frame fills its own used entries before reading them.

| Port group | Meaning |
| --- | --- |
| cfg_valid/ready, cfg_op[1:0], cfg_symbol[31:0], cfg_length[31:0], cfg_tag[TAG_W-1:0] | Configuration transaction:0 LOAD length,1 BUILD,2 QUERY,3 CLEAR, exactly as in the B31 codebook |
| cfg_r_valid/ready, cfg_r_op[1:0], cfg_r_status[2:0], cfg_r_code[MAX_BITS-1:0], cfg_r_length[31:0], cfg_r_tag[TAG_W-1:0] | Complete unchanged codebook response |
| c_valid/ready, c_count[31:0], c_tag[TAG_W-1:0] | Accept one frame's declared symbol count and opaque tag |
| s_valid/ready, s_symbol[31:0] | Symbols in original order; exactly c_count handshakes for a valid-length frame |
| m_valid/ready, m_data[7:0], m_last, m_valid_bits[3:0], m_tag[TAG_W-1:0] | Encoded bytes, final-byte marker, meaningful bits1..8, captured frame tag |
| d_valid/ready, d_status[2:0], d_error_index[31:0], d_bits[31:0], d_tag[TAG_W-1:0] | One completion after the final byte retires, or after all erroneous-frame inputs are consumed |

Every transfer is valid&&ready with reset low. Configuration has priority over a frame command when both sources are valid in idle. Once accepted, either configuration owns the interface through its response retirement, or a frame owns it through completion retirement. There is no retirement-edge fallthrough, and configuration cannot change an in-progress frame. Infinite configuration traffic can starve frame admission. All valid outputs, payloads and metadata remain stable under backpressure. No input symbol is accepted on the frame command edge.

Configuration behavior is the original codebook contract: LOAD changes staging only; BUILD atomically activates a valid nonempty prefix code; empty/oversubscribed BUILD retains the previous active table. Incomplete nonempty trees and all-ones codewords are accepted. QUERY is available through the configuration port. CLEAR invalidates active and staging code lengths. Full32-bit symbol/length fields are validated before narrowing. See [the dependency contract](../canonical_huffman_table/README.md).

## Frame, error and bit order contract

Counts0..MAX_FRAME are legal. Count0 completes successfully without inputs or bytes, even with no active table. Larger full32-bit counts produce status6 immediately, with no input acceptance. A positive valid count always consumes exactly that many symbols. Each symbol is checked against the active table in order. The first bad symbol sets its zero-based error index; later symbols are consumed and discarded without lookup. There are no output bytes from an erroneous frame, including an error at the final symbol. If the producer stops before the declared count, completion waits indefinitely; reset cancels that ownership.

Frame status is0 OK,1 BAD_SYMBOL,4 NO_TABLE,5 ABSENT,6 BAD_FRAME_LENGTH. Values2 BAD_LENGTH and3 BAD_TREE belong to configuration responses and are not generated by frame processing. Error completions have d_bits=0; BAD_FRAME_LENGTH and successful frames have error_index=0. No stale codes can become output after an error. Rejecting a frame does not modify the codebook, and the next correctly configured frame can be accepted after completion retirement.

For every successful symbol, transmit its codeword from most-significant meaningful bit to least-significant bit. Concatenate codewords, then form bytes from left to right; the first transmitted bit occupies m_data[7]. The final partial byte is padded with zero least-significant bits. Nonfinal bytes have m_valid_bits=8; the final byte has1..8. An exactly byte-aligned frame has no extra padding byte. Only the final byte asserts m_last. Byte0xff is emitted unchanged without a following stuffed byte. d_bits is the sum of original code lengths, excluding padding, and is bounded by MAX_FRAME*MAX_BITS. An empty/error frame has no m_last byte; its completion defines the transaction boundary.

## Architecture and feasibility

The codebook is reused by exact source reference. Each input symbol is followed by a private codebook QUERY and response. A successful result writes a bounded code/length entry. After all lookups pass, one synchronous array fetch loads each symbol and a one-bit-per-cycle serializer builds an eight-bit output register. It pauses while each byte is held. Full-frame buffering trades latency for rejection without partial compressed output; there is no host-produced codeword input or output image.

Code/length buffering is MAX_FRAME*(MAX_BITS+ceil(log2(MAX_BITS+1))) logical bits:5376bits at defaults. The unchanged codebook contributes12,032bits at default SYMBOLS/MAX_BITS, for17,408 total logical payload bits. At maximum MAX_FRAME1024 the extra buffer is21,504bits. Array inference and physical RAM packing are unmeasured. There are no multiplier operators, vendor primitives or external memory ports. Qualitative risk is MEDIUM for memory inference and serializer throughput; no LUT/DSP/BRAM count, Fmax, power or actual device-fit measurement is claimed.

With a ready codebook, each symbol lookup occupies three clocks from input acceptance to the next possible input acceptance. Emission uses one fetch cycle per symbol, one cycle per useful bit and at least one retirement cycle per output byte. With continuous input valid and always-ready byte/completion sinks, `4*N + B + ceil(B/8) + 4` is a conservative bound from frame acceptance to completion-valid for N>0 and B encoded bits. Configuration and initialization are excluded. Arbitrary source gaps and output stalls add latency and remove any unconditional completion deadline. Empty and invalid-length completions become valid immediately after their command acceptance edge.
