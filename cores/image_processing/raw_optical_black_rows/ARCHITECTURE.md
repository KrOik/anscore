# B42 architecture review

The selected function is row-local black measurement from declared sensor margins plus active crop. It preserves a measured offset epoch through an actual unchanged correction module. It does not replace the whole-frame ROI estimator or add another manual offset width.

A whole-frame store could postpone all output until errors were known, but would require WIDTH*HEIGHT*BITS storage and frame-scale delay. A single active-row buffer uses WIDTH*BITS bits, permits references on both sides of the active area, and confines memory to 1280 bits by default or 6144 bits maximum. A two-row ping-pong buffer could overlap capture and replay, but would double storage and complicate row/config ownership. No uninterrupted sensor rate was required, so the selected design explicitly backpressures input during estimation and replay. The caller must support that service contract or provide an upstream capture buffer.

Each parity has at most32 references: each margin is at most32 columns. At RAW12, sum<=32*4095=131040 needs17 bits. count1..32 needs6 bits. Adding floor(count/2) gives at most131056, still17 bits. The resulting quotient is at most4095. A single unsigned restoring divider performs17 iterations per mean and is reused for both means. Trial remainder uses7 bits; stored remainder is less than denominator<=32 and fits6 bits. No run-time multiply, reciprocal ROM or combinational divide is instantiated.

Capture stores only active samples into one synchronous row RAM. Capture and replay are mutually exclusive, so same-address read/write collision semantics are never consumed. The control reset invalidates the frame and output state without clearing the memory. A legal row overwrites every active location before any replay. A synchronous read register and issued index give II1 replay bursts while preserving output under backpressure. Two means, the target and row metadata remain fixed until a fully acknowledged fence.

The core FSM is IDLE, CAPTURE, CHECK, DIV_INIT, DIV_STEP, DIV_STORE, ROW_CFG, REPLAY, FENCE, DONE. Successful row preparation takes39 clocks after final capture to expose ROW_CFG: CHECK1 plus two sequences of INIT1/STEP17/STORE1. Configuration, RAM/output fill and drain add bounded control cycles. Always-ready consecutive sensor-row starts are within `sensor_width+WIDTH+48` clocks in both core and supplied frontend; backpressure extends this interval. Output bursts can be II1, while the input is stopped during those bursts. These are source-derived cycle bounds without physical clock evidence.

The old correction contains one elastic output slot. Accepted raw input increments the wrapper's2-bit owned count, final accepted public output decrements it, and simultaneous transfers leave it unchanged. Because old readiness permits a new raw pixel only if the slot is empty or retiring, owned is structurally0 or1. Row configuration requires owned0, old m_valid0 and no active row. The fence requires owned0 and old m_valid0 before releasing that epoch. Thus black/pattern/y/tag cannot change while an old output is held. Terminal DONE can arise only after a completed fence or during input capture with no old owned pixels. Invalid configuration accepts no pixels. Reset also resets the old module through an explicit polarity adaptation; its internal asynchronous assertion is retained honestly.

Default storage risk is LOW, control/service risk MEDIUM because each row interrupts sensor input, and maximum storage remains6144 logical bits. DSP inference, BRAM fragmentation, LUT/FF mapping, power, achievable Fmax and target-device fit remain UNKNOWN/HW_UNVERIFIED. The block is portable RTL with no external memory or vendor hard IP. The 17-bit serial divider is selected for bounded storage/arithmetic and maintainability, not from measured PPA.

The independent oracle derives reference lists by coordinates and computes nearest-half-up using `(2*sum+n)//(2*n)` rather than reproducing the serial divider. Its one authorized preparation will audit all2837040 legal BITS/sum/count tuples (BITS8:134672; BITS10:540176; BITS12:2162192), then prepare24 vector files before the first HDL child. RTL checks cover the maximum count/sum/rounded numerator using RAW12 with32+32 reference columns.

Four finite profiles are core1x1 RAW8/TAG1, core7x5 RAW10/TAG8 with odd crop, core17x9 RAW12/TAG32 and32+32 margins, and actual32x8 RAW10/TAG8 with odd crop. Sixteen scenes per profile run dense and independently stalled: row drift/parity offsets, both clamps, half means, excluded hot reference, equality thresholds, three invalid configs, missing even/odd references, bad SOF/EOL/LAST, seeded arbitrary samples, and maximum references. Config pins change after command acceptance. Four reset cuts interrupt partial capture, divider, held output and held DONE, each followed by checked healthy recovery. Every profile has40 commands,36 retired DONEs,5 resets and4 cancelled commands; planned exact output counts18/784/3400/5696 total9898. Row config, held payload, old frame ID, owned capacity, drain fences and terminal drain receive explicit checks. Maximum512x128 receives syntax only.

The frozen runner permits exactly11 HDL children:3 syntax checks and4 compile/sim pairs. Each child has20 seconds, then tree kill5 seconds and pipe drain2 seconds. One failure stops the suite, with no automatic retry or cleanup. Exact source/plan/tool bytes are hashed and archived before the one oracle import/preparation; every child rechecks those hashes and the24 prepared vectors. Archive basenames end in `.executed.txt`, including the archived attribute file, so archived attributes cannot activate. Local `* -text` preserves all formal/archive raw bytes.
