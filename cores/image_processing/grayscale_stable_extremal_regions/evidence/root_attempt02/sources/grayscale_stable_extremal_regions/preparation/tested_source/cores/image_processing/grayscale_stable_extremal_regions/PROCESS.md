# Source freeze and future execution boundaries

All preparation, reference, fixture, HDL, synthesis, PnR, STA and board work
remain NOT_RUN. Repair01 used external standard-library source writes,
AST/JSON parsing and byte hashing only. The original30-file revision and its
author report remain preserved outside the package.

AUTHOR_SEAL binds all source, plans, inputs, the max-tree dependency and six
anchors. TOOL_INVENTORY is a self-contained byte copy of the independently
reviewed B static record: three tools, ordinary/delay PE import resolutions,
transitive local/Python runtime closure, Windows API-set treatment and system
dependencies, all31 Python extensions, all39 compiler/VPI-directory files,
and exact six DLL/PYD search-directory inventories. runtime.py is a local copy
of its pure byte guard. Every child boundary rechecks this complete record.
No inherited PATH, PYTHONHOME or PYTHONPATH enters a child; the fixed approved
environment also disables user site packages and bytecode writes.

Future preparation requires schema anscore-b30-c-prepare-once-v2, approved_by root, exact AUTHOR_SEAL/PREPARATION_PLAN,
child_argv template, max_invocations1, hard_seconds20, automatic_retry false
and at least two frozen independent static-review path/hash anchors. The gate
requires the exact unprepared inventory and exclusively creates preparation.
It copies the complete approved source/seal, sole production dependency, all
anchors and the approved review bytes into preparation/tested_source with
repository-relative paths.
The original approval is preserved byte-for-byte as approval.json.

CONTEXT binds original approval path/digest, reviews, author/plan, fixed
environment, explicit output root and exact tested-source map. LOCK captures
the context digest and once-only identities. The child argv expands only the
approved template: copied prepare.py, explicit output/context paths and exact
context/LOCK digests. The copied child verifies these bytes and its exact
argv/cwd before importing its copied reference. It evaluates exactly30 main
and10 fresh frames, materializes10 unsolved probes, and writes exactly34
fixture files. It checks stored consistency, repeats context/source/runtime
guards, then writes a fixed payload manifest with those hashes and counts.

Raw streams are persisted before validation. PASS requires exact argv/cwd/env,
exit0, no timeout/failure, elapsed below20 seconds, positive pid, explicit
suspended creation, Job assignment before resume, and successful kill-on-close
Job closure. Exact stdout and empty stderr are checked. The seven fixed
evidence files are CONTEXT.json, LOCK.json, approval.json, payload.json,
receipt.json, stdout.raw and stderr.raw; every tested_source file is also
retained. The exact inventory rejects additional files, including temporary
files left behind. No timing or PASS claim is made by this source authoring.

SOURCE_SEAL schema2 includes every author source/seal, exactly34 fixtures and
the complete evidence/copy inventory. It captures context/LOCK/PASS-receipt
digests. verify_source re-derives this inventory and rechecks the original

process metadata and exact raw hashes/sizes/content before HDL setup and at

self-consistent replacement receipt without changing the approved seal.

TEST_PLAN, all26 child definitions, max_invocations1, hard20, no retry and two

process_tree.py retains its reviewed suspended Windows spawn, Job binding,
resume, hard20 deadline and bounded cleanup mechanics. Repair01 adds explicit
containment/argv/cwd/environment receipt fields; its original bytes remain

adopted. Every post-directory exception is terminal FAILED_STOPPED and retains
