# B41 architecture review

The selected task is a bounded same-clock pixel service, not a frame renderer. It closes the retained-destination-alpha gap rather than adding another width of RGB source-over.

Parallel products are selected because paired pixels may arrive densely and no slower service rate was authorized. A shared multiplier would need at least eight work cycles per composed pixel plus conversion work, breaking II=1 bursts. Registering product, sum and quantization separately isolates the multiply/add/round chain. Global stall simplifies complete metadata ownership and uses three token slots. A distributed elastic pipeline might absorb bubbles more aggressively during downstream stalls, but would increase local ready/control logic; it is not required by this contract.

Unsigned byte products are 0..65025; the two-product sum is 0..130050 (17 bits). Clamping before the bounded divide fold avoids a 17-bit plus-wrap error. Error tokens take the same stages as good tokens, so ordering and backpressure are shared. Component and alpha use identical coefficients and quantization: `Cs<=As` and `Cd<=Ad` imply `Cs*Fa+Cd*Fb <= As*Fa+Ad*Fb`; monotone rounded saturation preserves premultiplication.

The pair adapter has six 8x8 products and two output registers. With the core, this means fourteen conceptual byte multipliers, not a measured count of DSP blocks. Arithmetic has no RAM, ROM, divider or vendor primitive. Core storage is fixed payload registers plus three copies of bounded metadata; adapter storage is fixed products/output plus two copies of metadata. No parameter creates an unbounded data array in the new arithmetic.

The two old samplers retain their original synchronous RAM access and mutually exclusive write/read modes. Each has `8*W*H+256*32` logical RAM bits. Default two 8x8 banks use **17408 bits**; maximum two 256x256 banks use **1064960 bits**. Default risk is LOW for storage, MEDIUM for parallel arithmetic and the ready path; the maximum storage profile is HIGH and only a syntax case. Physical BRAM fragmentation, actual DSP mapping, power and achievable clock remain UNKNOWN/HW_UNVERIFIED. No target device or measured PPA was supplied.

The wrapper's strict atomic query fanout and response join maintain identical x/y/tag/mode for the two samplers. The 4-bit owned counter counts final output acceptance, so eight maximum occupied stage slots cannot overflow it. There is no independently accepted half-pair. Command forwarding requires owned=0 **and** every component's busy signal low; this extra condition keeps admission tied to actual stage drain. A waiting command suppresses only new public queries and cannot assert an old sampler `c_valid` early (which would otherwise suppress lookup readiness). A single command-response owner fixes bank selection through response backpressure.

The finite numerical oracle uses direct arbitrary-width integer division, independent of the RTL shift fold. Before first HDL, the plan prepares all vectors and audits every T in 0..130050, all 851968 alpha/mode combinations with four color extrema (3407872 closure checks), and all 65536 straight component/alpha conversion pairs. The monotonicity argument covers intermediate colors without pretending to enumerate all RGBA pairs.

Two core profiles cover TAG_W1/32, all modes, invalid opcodes and source/destination/error priority, directed alpha boundaries, dense II1 output bursts, independent source gaps and output backpressure, and reset at each of the three live stages. Two actual composition profiles cover 1x1/TAG1 and 8x8/TAG28, two complete resident loads, all opcodes, transparent and out-of-range samples, changed palette/index epochs, held management responses, pending BEGIN behind held composed output, and reset of owned output and response. Maximum dimensions receive syntax only. Watchdogs are finite and comparisons are exact; failures stop the run and retain all evidence.

The runner freezes every executed dependency and exact bytes before oracle execution, records SHA256 for current inputs, archives, vectors and tools, checks immutability before each child, and keeps stdout/stderr plus ordered receipts. Each child has 20 seconds, then at most 5 seconds tree kill and 2 seconds pipe drain. There is no automatic retry or cleanup. Root owns staging/committing; retained historical failures and images are untouched.
