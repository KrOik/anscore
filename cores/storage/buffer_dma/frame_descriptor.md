# Frame/block descriptor and slot ownership v1

Descriptor width is 66 bits. A descriptor may represent a tile, line or bounded
block; it need not represent an entire video frame.

| Bits | Field |
|---|---|
| 65:50 | opaque 16-bit frame/block ID |
| 49 | producer 0/1 |
| 48 | consumer 0/1 |
| 47:16 | byte-aligned base address generated by slot manager |
| 15:0 | payload count in 32-bit words, not bytes |

## Ring

frame_descriptor_ring is a same-clock, synchronous-read queue. DEPTH is a
power of two, 2..256 (default8). Capacity is exactly DEPTH INCLUDING the
registered output slot. Full occupancy permits simultaneous pop/push with no
capacity increase. There is no empty bypass; fetch starts after the RAM write.
After prefetch, continuous push/pop can sustain one descriptor per clock.
Input and output must obey valid/ready stability. Reset invalidates all queued
descriptors and resets occupancy/high-water/blocked-cycle counters, without
clearing RAM/data registers. Ignore data when valid=0.

The ring preserves all 66 bits and performs no address/length validation. A
full queue backpressures; it does not drop descriptors. blocked_cycles counts
valid&&!ready cycles, not lost data. RAM_STYLE defaults to auto so small queues
may map to distributed RAM; RAM_STYLE="block" can request block RAM. Both are
synchronous RTL reads; actual mapping/resource cost must be measured.

## Four-slot manager

frame_slot_manager tracks FREE -> WRITING -> QUEUED -> READING -> FREE.
There are two producers and two consumers. Each producer has at most one
WRITING slot; each consumer has at most one READING slot. QUEUED slots retain
ownership until consumed and completed. The payload memory is external.

SLOT_WORDS is a power of two,1..32768, default256. Slot i has base
`i*SLOT_WORDS*4`. The backing RAM must have at least `4*SLOT_WORDS` words;
do not connect manager defaults to the foundation's DEPTH256 RAM unchanged.
Use DEPTH1024 for SLOT_WORDS256. Physical resource limits apply independently.

FIXED_PINGPONG=1 (default) reserves slots0/1 for producer0 and2/3 for producer1.
Successful allocations alternate banks. If the next bank is still owned,
allocation stalls even when another bank is free. FIXED_PINGPONG=0 uses a shared
four-slot pool instead. Arbitration of allocations and write completions is
round-robin. Allocation responses have independent valid/ready storage.

Allocation samples length/frame ID/destination on its request handshake. A
length outside1..SLOT_WORDS returns allocation error without reserving a slot.
A producer must consume its allocation response before completion is accepted,
and must wait for all payload writes to complete before asserting w_done.
Successful w_done publishes one descriptor into the selected consumer's queue;
w_error frees the slot without publishing. The consumer sees complete-write
descriptors in commit order, not necessarily original allocation order across
producers. A stalled consumer cannot cause its slot to be overwritten.

After accepting a descriptor, a consumer must finish all reads and signal
r_done before the slot is freed. r_error still releases the slot and records an
abort. Completion without current ownership is not accepted. The controller
trusts producer/consumer completion; it does not inspect individual memory-port
addresses or act as a protection firewall. RTL block movers must enforce bounds
and report actual completion in the next integration stage.

Counters: published counts successful write commits; released counts all read
completions, including errors; aborted counts write/read error completions;
invalid_requests counts rejected allocation lengths. All counters wrap at2^32.
Reset jointly aborts queued, writing and reading ownership; reset the DMA and
memory-port controls together. RAM payload persists and must be overwritten
before publishing a new descriptor. These modules contain no CDC.

## Slot lifetime telemetry

Additional outputs on frame_slot_manager: latency_last/min/max/sum contain two
32-bit consumer slices (consumer0 low). Successful read completion records the
cycle difference from successful allocation request acceptance to read completion
acceptance. This includes payload input, memory arbitration, descriptor queue,
output backpressure and completion submission. It differs from the passive
stream's first-to-last transfer duration. Aborted writes and failed reads do not
update latency. Min resets to FFFFFFFF; last/max/sum reset to zero. Timestamp
subtraction and sums wrap modulo 2^32; a slot lifetime must be shorter than 2^32
clocks for interpretation. elapsed_cycles is free-running since control reset.
allocation_stalls sums valid-without-ready producer cycles (0..2 per clock);
this includes arbitration/producer-busy waits, not only all-slots-full waits.
peak_occupied records the maximum non-FREE slots sampled at clock edges.
Reset clears all telemetry and timestamp state. No separate telemetry clear is
provided, because clearing timestamps mid-frame would invalidate measurement.

Integrated scoreboard evidence: frame_buffer_20261020T163433254741Z. Both modes
check all completed-slot latency last/min/max/sum against independent timestamps,
exact allocation wait cycles, elapsed clocks and peak occupancy=4. Fixed-mode
consumer0 last/min/max/sum =149/26/306/3463 cycles; consumer1 =158/25/308/3427.
The manager regression also passes (slots_20261020T163435974680Z), including error
and reset recovery. This finite simulation is not physical throughput evidence.

### GW5A placement correction

The slot manager now requests RAM_STYLE=block for its two descriptor queues.
The first narrow-top build (board_20261020T164928239302Z) failed placement because
automatic inference produced RAM16SDP4 cells without placeable GW5A BELs in the
current toolchain. Its failed logs are preserved. This change preserves queue
capacity/semantics but changes inferred physical storage; old distributed-RAM
resource reports do not describe the current manager. Regressions test_slots.py
and test_control.py pass after the change (slots_20261020T165633859740Z,
control_20261020T165639846902Z). Updated route/resource evidence is pending in
board_20261020T165642947154Z; no physical resource/Fmax claim until completion.

Latency telemetry now commits one clock after successful read completion:
latency_delta first captures the original timestamp difference,then last/min/max/
sum update from that registered delta. Physical measurement endpoints and values
are unchanged. A same-edge CSR snapshot can therefore include the released count
before its latency aggregate update; quiesce until selftest done or wait a clock
when interpreting completed-frame aggregates. Independent timestamp regression
frame_buffer_20261020T171542841254Z passes after pipelining.
