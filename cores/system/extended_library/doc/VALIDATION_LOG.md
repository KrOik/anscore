# wave2_ip_20k Validation Log

Second-wave IP batch for Sipeed Tang Primer 20K
(Gowin GW2A-LV18PG256C8/I7, 27 MHz board clock, UART 115200).

40 selftest units (`st_<unit>` contract: clk/clk_en/rst_n/start ->
done/pass/digest/cycles), aggregated by `src/w2_selftest.v` behind a
40-bit `UNIT_EN` mask; board report generated by `src/top.v`
(UART header + one 32-char line per unit).

Golden values come from independent Python models in `tools/golden_*.py`
— never from RTL simulation.  All pass/fail verdicts use `===`/`!==`
so X cannot fake PASS.

## Board validation

Per-group bitstreams on Tang Primer 20K, UART report captured at
115200 on COM24 (`doc/board_uart_g<N>.txt`).

**IMPORTANT**: all board bitstreams must be built with
`synth_gowin -noalu` (`build_wave2_ip_with_oss.ps1 -NoAlu`).  The
first ALU-enabled build produced a deterministic CSC failure that was
root-caused to a GW2A ALU carry-cell toolchain defect — see
"CSC silicon failure / ALU root cause" below.

### CSC silicon failure / ALU root cause

With ALU cells enabled, CSC (U04) failed deterministically on the
board: digest `EF23D9F6` (group image) / `C26EF261` (debug image)
instead of golden `CE41D92D`, while RTL sim, the yosys-sim'd gate
netlist, and the other 39 units were all correct.

Debug path: `src/top_cscdbg.v` streams every `isp_csc` output byte
over UART (`sim/tb_cscdbg.v` verifies the transport end-to-end,
6156 bytes, 0 mismatches in sim).  Board capture
(`doc/board_cscdbg_raw.bin`) showed only **56 of 6144 bytes wrong,
all in output channel 2** (Cr in fwd mode / B in inv mode) with small
value-dependent deltas (±2..±28) — impossible under timing
(inputs stable 8192 clk per beat) and inconsistent with RTL/netlist.
Different placements produced different wrong digests.

Rebuilding with `synth_gowin -noalu` (LUT-only arithmetic, no Gowin
ALU carry cells) produces a bitstream whose board UART dump matches
golden byte-for-byte (0 errs, trailer `D=CE41D92D`,
`doc/board_cscdbg_noalu capture`), and the group image then reports
`U04 CSC  P D=CE41D92D`.  => **Root cause: incorrect results from
GW2A ALU cells in the OSS nextpnr-himbaechel/apycula flow for
specific carry patterns**, not an RTL bug.  All group bitstreams were
rebuilt with `-noalu`.

## Board-level real-timing verification (`top_hwverify`)

A dedicated board-verification image exercises all eight requested areas in
one bitstream: reset timing/synchronisation, PLL lock, CDC + metastability
instrumentation, datapath throughput, boundary/exception handling, register
bus read/write, low-speed interfaces, and physical timing margin.  Host
access is a UART command protocol (`W/R/P/T`) on COM24 @115200 plus an
8-channel LA probe mux on pins A11 B11 N6 D11 N9 N7 L9 N8
(`probe_sel` 0..4).  RTL: `src/top_hwverify.v`; sim TB:
`sim/tb_hwverify.v` + `sim/hv_sim_stubs.v` (`HWVERIFY TB PASS`);
build: `build_oss/hwverify.fs` (`synth_gowin -noalu`, nextpnr-himbaechel
GW2A-LV18PG256C8/I7); host script: `tools/hv_run.py`.

### Physical timing closure — real silicon margin

nextpnr STA is optimistic for this device: it reports domain Fmax
97-122 MHz while the CSC datapath actually fails on silicon at 54 MHz
(digest changes run-to-run: `7A32E12D`, `3E470D2D`, `3A9F112D`,
`56CC0F2D`, `20DB5CC8`, `9BF4192D` — nondeterministic marginal failure,
not a logic bug).  A second rPLL output adds a lower margin point.
Measured bracket for the `-noalu` CSC implementation:

    27 MHz PASS  /  33.75 MHz PASS  /  54 MHz FAIL
    => real Fmax in (33.75, 54) MHz for this build

The 54 MHz point is retained as a margin probe (`INFO`, non-gating);
aggregate `status_pass` gates on 27 MHz + 33.75 MHz only.

### CDC design bug found by placement sweep

The first hwverify placement reported 0 CDC errors; a rebuild after an
unrelated change reported ~34% error rate.  Root cause: the OSC-domain
producer incremented the shared counter and toggled `req` on the **same**
osc clock edge, so the consumer's 2FF-synced view of `req` arrived only
~74 ns after the data changed while the data needed up to one OSC period
(~420 ns) to settle — a placement-marginal multi-bit CDC read.  Fix: the
producer now updates `o_cnt` first and toggles `o_req` one OSC cycle
later (`o_pend`), guaranteeing the bus is quiescent >1 source period
before the request edge.  Post-fix silicon: 58294 transfers, 0 errors,
and the LA capture visibly shows the handshake rate halved as predicted.

### Notes / caveats

- The LA boot capture used `POR_BIT=25` build `hwverify_por.fs` (same
  RTL, longer reset stretch) so the ~152 us production POR becomes an
  LA-visible 1.24 s window; production image `hwverify.fs` uses
  POR_BIT=12 and is the 21/21 PASS bitstream.
- Metastability instrumentation counts tap disagreements; it is
  observability, not a statistical proof of metastability immunity.
- `hv_run.py` inserts ~0.5-2 ms between TX bytes: `uart_rx` holds
  `rx_valid` through an ack state and would drop back-to-back start bits.
- FT2232 COM24 wedged once during the session (0 bytes on known-good
  images, JTAG still fine) — recovered by re-plug; same failure as the
  earlier wave-2 incident.
