# 24xx I2C EEPROM transaction controller

`i2c_eeprom` implements complete random-address read, sequential read, automatic page-safe write splitting and post-page ACK polling. It includes the narrow `i2c_eeprom_phy` open-drain START/repeated-START/STOP/byte engine; physical timing and clock stretching run regardless of host CE. Existing generic I2C masters remain untouched. A whole-library filename/text audit found generic byte/stream I2C masters and an I2C register slave, but no equivalent EEPROM page/poll transaction controller.

Supported addressing is one word-address byte with capacity <=256 (24C02 style), or two word-address bytes with capacity <=65536 (24LC256/512 style). The seven-bit device address is a command input. 24C04/08/16-style bank bits embedded in the device address are not implemented; do not configure those devices as linear two-byte parts. The controller does not discover capacity/page size, emulate EEPROM memory internally, detect write-protect silently ignoring ACKed writes, or support rollback. Match actual device geometry and board timing before use.

## Host contract

This is a CE-qualified host interface, not a standard CE-free ready/valid interface. `start_ready` means IDLE availability and can remain high with CE=0. A command is accepted only on `ce && start_valid && start_ready`; write/device_address/word_address/length are snapshotted at that edge. `length` is 1..65535, and the entire range must lie within configured capacity, with no address rollover. `write=1` consumes bytes on `ce && tx_valid && tx_ready`; `tx_ready` itself is CE-gated. The host must preserve valid write data until acceptance.

`rx_valid` exposes a stable byte and `rx_last` until **ce && rx_valid && rx_ready**. Ready alone while CE=0 does not consume a byte, even if held longer than the write-host timeout. Do not attach a consumer that counts `valid && ready` without CE. `done_valid/error_code/bytes_completed` remain held until **ce && done_valid && done_ready**. Completed-byte count means ACKed write bytes or host-consumed read bytes; it is not proof of nonvolatile write completion on an error. Read backpressure holds SCL low between bytes. Write input starvation holds SCL low and eventually fails via HOST_TIMEOUT_CYCLES, which counts physical clocks including CE=0. No read-output timeout withdraws an exposed byte.

Each write page uses START, control-write byte, word address, up to the remaining page bytes, then STOP. The scheduler ACK-polls the control-write byte with separate START/STOP attempts before starting the next page or returning success. A busy NACK is retried only during this poll phase; an initial device-address NACK is an explicit failure. The read sequence is START/control-write/word-address/**repeated START**/control-read/data, ACKing every read byte except final NACK, then STOP. A page wrap in an actual EEPROM must never substitute for splitting.

## Timing and errors

Pins are inputs plus low-enable outputs. Drive the external line low only while its enable is one, otherwise release it; external pull-ups are required. Two-stage input synchronizers are included. HALF_PERIOD_CYCLES >=4 selects nominal low/high hold durations, with synchronizer and state-transition overhead. This is a timing divider limit, not a claim that every setting meets a particular I2C mode; choose clock/divider/pull-ups for the actual EEPROM datasheet. STRETCH_TIMEOUT_CYCLES >=4 bounds low-clock waits; startup busy and post-STOP stuck bus are bounded/explicit failures. POLL_LIMIT=1..65535 bounds address attempts, POLL_GAP_CYCLES>=1 gives bus-free delay, HOST_TIMEOUT_CYCLES>=1 bounds missing TX bytes. PAGE_BYTES is a power of two in 1..256 and <=capacity. ADDR_BYTES is 1 or 2; capacity is 1..65536 and <=256 with one-byte addressing. Invalid parameters or command ranges fail before START.

Error codes: 0 success, 1 control-address NACK, 2 word-address/data NACK, 3 clock stretch timeout, 4 arbitration lost, 5 busy/stuck bus, 6 ACK-poll limit exhausted, 7 host write-byte timeout, 8 invalid configuration/range. NACK and host-timeout paths attempt STOP; physical errors release both outputs immediately, and a physical STOP error supersedes the pending logical error. Arbitration is detected when a transmitted one is observed low, including final read NACK; the controller then releases the bus without issuing STOP. This is not a complete multi-master clock-synchronization/recovery implementation. There is no automatic nine-clock bus-clear sequence.

Synchronous reset takes priority with CE=0, cancels the host transaction on its clock, and releases both bus enables. It can interrupt a physical cycle and cannot undo bytes already accepted by the device. Device power-loss behavior and analog metastability/MTBF are outside the evidence.

## Verification and references

Run with `python -B`: `test_case.py`, `test_transactions.py`, `test_boundaries.py`, `test_errors.py`, `test_parameters.py`, `test_protocol.py`, and `synth.py`. All HDL products use auto-cleaned C: TemporaryDirectory; retained files are source, small logs, and source-bound JSON evidence. All Python text IO is explicitly UTF-8.

The independent device model watches physical SCL/SDA only. It implements address byte order, actual page-local write wrap, busy-cycle NACK polling, sequential pointer reads, and open-drain data/ACKs. Tests compare written device memory and returned data, so merely issuing the expected digest cannot pass. Cases include page sizes1/8/64/256, one-/two-byte addressing, last capacity byte, minimum legal divider, legal stretching, random repeated-START reads, long RX backpressure, CE0/DONE/command snapshots, control/word/data NACK, polling/host/stretch/busy timeouts, arbitration loss, reset, and illegal geometry/limits.

`fetch_references.py` actually retrieves RobTillaart I2C_EEPROM software and alexforencich/verilog-i2c RTL into memory, retaining SHA256 and short excerpts in references.json. These informed page-write bounds, ACK readiness and open-drain timing; this implementation does not import their code. Complete isolated scheduler+PHY `synth_gowin -nodsp; check -assert` uses 941/939/931 LUT-class cells for small/default/large parameter profiles, with 0 DSP and 0 BRAM. These are synthesis results, not routed timing, combined fit, real EEPROM or board acceptance.
