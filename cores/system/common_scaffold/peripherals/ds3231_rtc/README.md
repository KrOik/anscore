# DS3231 I2C RTC transactions

`ds3231_rtc` implements device transactions against the real DS3231 seven-bit address 0x68. It reads time/calendar, converts BCD and 12/24-hour mode, exposes status and rollover retry count, and writes a validated binary calendar as 24-hour BCD. It is not an internal ticking RTC counter. Whole-library read-only searches found only `ips_rtc_calendar` and generic I2C controllers, not an equivalent DS3231/DS1307 transaction controller. DS1307-specific CH/battery/RAM behavior is not claimed.

The new RTL directly instantiates the existing independently tested `i2c_eeprom_phy`. No old RTL was modified and no copied transport remains here. `dependency_sha256.json` records its SHA using a path relative to `cores/system/common_scaffold`, not an owner-escaping freeze key. Compile the primary source plus this dependency, as every test/synthesis script does. `rtl_sources.f` lists only the new primary source; an integration that already includes the shared PHY must not duplicate it.

## Command and output contract

The host is explicitly CE-qualified. Command acceptance is **ce && start_valid && start_ready**; `start_ready` means IDLE availability and can remain high with CE=0. `set_time=0` reads; `set_time=1` snapshots the binary set_year/month/day/weekday/hour/minute/second inputs. Year is 2000..2199, weekday1..7 is a caller-chosen consecutive numbering convention, and time is normalized 24h. Weekday is range-checked but not recomputed from the date.

Read results assert `result_valid` only after completion/validation. All date/time, status_raw, source_12h, source_century and retries remain immutable until **ce && result_valid && result_ready**. Ready with CE=0 does not consume the result. Status flags are meaningful as part of this valid snapshot; raw status may update internally before result_valid during a new read. Success or failure then holds done_valid/error_code until **ce && done_valid && done_ready**. SET_TIME emits DONE without a read result. Physical I2C timing continues through CE=0 after command acceptance. Reset is synchronous, has priority with CE=0, releases the shared PHY and cancels any exposed result; it cannot roll back device bytes already ACKed.

## Device behavior and consistency

READ_TIME uses three pointer-write/repeated-START/read/STOP phases: seven bytes at00..06, status byte0F, then seconds byte00. Every read ACKs intermediate bytes and NACKs its final byte. The DS3231 datasheet explicitly says its secondary user registers synchronize on any START and reads use these buffers; therefore the initial contiguous seven-byte read is already coherent. The extra seconds comparison is a conservative cross-phase rollover/freshness check, not a replacement for hardware shadowing. If the final raw seconds differs from the first snapshot, the complete three-phase sequence is repeated up to MAX_ROLLOVER_RETRIES (0..255 additional attempts). Exhaustion reports error6; this can occur during repeated normal cross-second reads and does not mean the DS3231 shadow snapshot itself was inconsistent. Comparison detects ordinary second transitions; it does not prove freshness across a full 60-second alias or an external writer changing other registers while seconds stays equal. Choose clock/stretch limits appropriate to the application.

BCD digits, reserved time-register bits, month/day bounds, 12-hour values1..12, 24-hour values0..23 and Gregorian leap rules are validated. 12AM becomes0, 12PM becomes12, and the PM flag adds12 for1..11. Century0 maps2000..2099 and century1 maps2100..2199; the century bit alone cannot identify a universal epoch. 2000Feb29 is legal; 2100Feb29 is rejected. This host validation does not repair or certify the chip's automatic leap-year behavior beyond the datasheet's specified range.

SET_TIME writes only00..06, with seconds first, then minute/hour/weekday/date/month+century/year. It forces24-hour mode. The datasheet resets the countdown chain when seconds is written and requires the remaining time registers to be written within one second; select system clock, HALF_PERIOD_CYCLES and stretch timeout to meet that integration constraint. There is no host pause inside the write transaction and no readback/rollback guarantee on an interrupted write.

Status0F is read intact. `oscillator_stop=status_raw[7]`, `alarm1_flag=status_raw[0]`, and `alarm2_flag=status_raw[1]`. OSF does not suppress an otherwise syntactically valid time: software must decide whether that time is trustworthy. This controller never clears OSF/alarm flags or alters control/alarm registers; alarm scheduling, alarm interrupt handling, temperature, aging offset and oscillator configuration are outside scope. In particular SET_TIME does not silently clear OSF.

## Timing and errors

Use external pull-ups and open-drain low-enable pins. HALF_PERIOD_CYCLES>=4 and STRETCH_TIMEOUT_CYCLES>=4 are physical clock-cycle parameters; they do not by themselves certify standard/fast I2C mode or routed FPGA timing. The shared PHY includes input synchronizers, clock stretching, transmitted-one arbitration checks and bounded bus waits. It releases both outputs on physical errors. It does not implement complete multi-master clock synchronization or automatic nine-clock bus clear.

Errors:1 NACK on any transmitted control/pointer/data byte;2 malformed BCD/reserved bits or invalid device calendar;3 stretch timeout;4 arbitration lost;5 busy/stuck bus;6 rollover retry exhaustion;8 invalid parameters or SET calendar. Logical NACK attempts STOP; a physical error during STOP supersedes the pending NACK. No partial read result is exposed on errors.
