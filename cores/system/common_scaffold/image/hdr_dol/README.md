# RAW 2-exposure DOL demultiplexing and HDR merge

This directory provides two standalone synthesizable modules in
`raw_hdr_dol.v`, with no dependency on the 48 board-qualified IP snapshots.
Repository search found AWB feedback and LSC already implemented under
`image/isp` and `dsp_isp_library/isp/lsc`; no RAW DOL/HDR merge equivalent
was found. These modules fill that distinct missing function.

## Active-row input contract

`raw_dol2_demux` accepts active RAW pixels, BITS=8/10/12, static positive
WIDTH/HEIGHT. Each logical row is delivered as WIDTH long-exposure pixels
(`s_short=0`), then WIDTH short-exposure pixels (`s_short=1`). Repeat for
HEIGHT rows. `s_sof` appears on only the first pixel of the first LONG row;
`s_eol` appears at the end of every physical active row. A front-end must
remove sensor line headers, blanking, optical-black rows, and DOL offsets
before this interface. This is not a vendor-specific sensor DOL parser.
The samples must already represent the same sensor coordinate and CFA phase.

Two WIDTH-deep synchronous memories capture one long/short row. Once both
are received, paired `{long,short}` pixels are emitted with SOF/EOL for the
logical image. A read clock precedes each valid output; absent stalls,
output II=2 enabled clocks. Row capture and output do not overlap, and input
ready drops while the pair row is emitted. There is no full-frame storage.
Incorrect exposure tags or SOF/EOL set sticky `protocol_error`; geometry
continues by counters, so reset is the explicit resynchronization operation.

## HDR radiometric merge and motion rejection

`raw_hdr2_merge` consumes the paired stream. BITS and geometry must match
the demux; it can also accept paired data directly from another aligner.
Output width is BITS+8 bits, preserving extended radiance on the LONG scale.
It does not tone-map back to a display bit depth.

For input L,S and configuration values:

```
a = max(L - black_long, 0)
b = min(2^(BITS+8)-1, round_half_up(max(S-black_short,0)*ratio_q8/256))
high = blend_low + 2^blend_shift
w = clamp(floor((a-blend_low)*256 / 2^blend_shift), 0, 256)
motion = deghost && abs(a-b) > motion_threshold
output = a                              if motion && a < high
         round_half_up((a*(256-w)+b*w)/256) otherwise
```

Below the transition the low-noise long exposure wins; above it the short
exposure protects highlights. A per-pixel normalized exposure discrepancy
selects long exposure below the saturation region to reject inconsistent
short samples. Saturated/high-region long samples always use short exposure.
`m_motion` reports the discrepancy even in that high region. This is an
explicit local deghost policy: it does not estimate motion vectors or repair
rolling-shutter geometry. Sensor matching, black calibration and thresholds
are system inputs. CFA samples are processed independently, preserving RAW
phase and ordering; no demosaic or spatial color interpolation is involved.

## Configuration, flow control and reset

Merge configuration is atomic via `ce && cfg_valid && cfg_ready` only while
between input frames **and** the previous output has drained. Hold the bundle
until accepted. A config asserted mid-frame cannot alter that frame. Input
is paused for configuration when idle. Legal ratio is 256..65535 (Q8,
1..255.996). Black levels and blend_low use BITS-bit unsigned values;
blend_shift=0..BITS, and `blend_low + 2^blend_shift` must be <=2^BITS-1.
Motion threshold uses BITS+8 bits. An illegal bundle sets sticky cfg_error
and retains the previous complete config. Reset defaults are ratio=1,
black=0, blend_low=0, blend_shift=BITS-1, deghost disabled.

The merge is an elastic one-register stage with II=1 enabled clock when not
backpressured. Output markers are generated by logical geometry, and wrong
accepted input markers set sticky protocol_error. Both modules use transfer
`ce && valid && ready`: CE-qualified endpoints are required. CE=0 freezes
all sequential state and output payload/markers; valid may stay asserted.
Input ready and config ready are low during CE pause. Backpressured outputs
remain stable. Synchronous active-high rst overrides CE, aborts pending data,
clears errors, and restarts frame coordinates. The memories are not reset;
full row capture always precedes replay.

## Verification and resource evidence

From repository root:

```
python -B cores/system/common_scaffold/image/hdr_dol/test_hdr_dol.py
python -B cores/system/common_scaffold/image/hdr_dol/synth_hdr_dol.py
```

The Python reference evaluates normalized radiance and convex blending using
integer rational arithmetic; no DUT outputs feed the oracle. Generated SV
checks 12 geometry/bit-depth cases, six independently configured frames per
case, 972 exact HDR output samples, nearest transition boundaries, maximum
exposure ratio, black-level floor, deghost decisions and highlight policy.
Random input gaps, CE pauses and output backpressure exercise stream flow;
output data, motion flag and markers are checked for stall stability. Illegal
ratio/shift configurations retain prior output behavior, wrong exposure and
marker inputs set diagnostics, reset abort clears pending state. Six illegal
module/parameter combinations fail elaborated simulation. Temporary binaries
and fixtures are deleted automatically; only small JSON summaries remain.

Isolated `synth_gowin`, BITS12 WIDTH64 HEIGHT33, without family/P&R:

| module | LUT1-4 | ALU | FF | DSP | memory |
|---|---:|---:|---:|---:|---|
| demux | 117 | 12 | 42 | 0 | 24 RAM16SDP4 |
| merge | 302 | 216 | 116 | 4 MULT18X18 | none |

MUX5 counts are separate in synthesis_result.json. The combined datapath
uses four DSP-class cells under this mapping. Larger line buffers can map
to BRAM; no board timing/resource claim is made for unbuilt configurations.
There is no P&R or hardware validation yet.
