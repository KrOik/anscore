# Bounded complete-frame rate converter

This IP converts temporal frame cadence by selecting the latest complete captured frame at each rational output event. It stores three complete frames and genuinely re-reads the selected frame for repetition. It performs no interpolation or motion compensation. Existing external-memory cip_image_framebuffer capture/replay, video_dma_2d transfer and FIFO video_rgb_scanout lack this independent complete-frame cadence policy.

`cadence_tick` is a synchronous reference-time pulse, independent of input video frame arrival. `cfg_rate_num/cfg_rate_den` specifies output events per reference pulse, not an input/output ratio. Require1<=num<=den<=65535. A phase accumulator starts at0, addsnum per reference tick, emits due when sum>=den, then subtractsden. Example120Hz reference: input30fps arrives every4ticks, output60fps uses1/2; input60fps every2ticks, output30fps1/4; input24fps every5ticks, output30fps1/4. Rational values such as7/11 also work. No clock-frequency or physical display timing generator is implied.

START latches geometry/rate. Input ready/valid carries exact SOF/EOL/LAST markers. Frame IDs start0 and advance on each successfully completed input frame. Only a complete frame is atomically published. In-progress pixels never become visible. Three synchronous RAM banks represent capture, latest complete, and active output, allowing references to latest/active to share one bank. A free-bank selector excludes both newly published and currently active/being-launched banks. RAM is not reset; publication validity is reset.

Each due event selects latest complete as it existed before that clock edge. Publication on the same edge becomes eligible next due. Output latches its bank and ID until every pixel of that frame is accepted. Subsequent publication cannot overwrite the active bank. Output RAM reads are synchronous with a held ready/valid token; SOF/EOL/LAST and frame_id remain stable under backpressure. Repetition issues fresh reads of the same complete bank. Pixels are tightly stored, frame geometry is fixed per START, and only one output frame can be active.

Due while output active is dropped and increments tick_overrun_count. There is no unbounded request queue. This includes due coincident with accepting the final output pixel: the old active state wins, so it remains an overrun. Due without any published frame increments underrun_count and emits no partial/black frame. A later due may use the newest complete frame. The selected temporal cadence is latest-complete; congestion can change which input frame is selected, and the counters explicitly report congestion.

Counters are32-bit modulo2^32. published_count counts complete valid captures; output_count counts fully accepted output frames; repeated_count increments when a launch selects the same ID as the preceding launch. dropped_count increments immediately when publication replaces an older latest frame that has never been selected by any output launch. A launch on that same edge protects old latest from drop accounting. The final latest frame still waiting at stop is not a publication-replacement drop. tick_overrun_count counts discarded output requests and is distinct from dropped input frames. underrun_count counts due events with no complete frame.

CE gates START, input acceptance, output acceptance, abort and DONE acknowledgment. The cadence accumulator, output requests and synchronous output prefetch continue without CE; CE-off can therefore cause congestion while the exposed token remains stable. Abort is CE-qualified, blocks new input/publication/output launches, discards partial capture, and drains the entire active output frame before DONE/error9. Thus DONE can wait indefinitely for the downstream receiver; no silent timeout withdraws accepted frame obligations. Bad input markers stop capture with error2 and similarly drain an existing output frame. A same-edge due may launch the previously published frame before the bad marker is detected; it too drains completely. Reset synchronously clears active state and exposed output, discarding all stored-frame validity. After DONE acknowledgment, START reinitializes counters and restarts cleanly.

Legal static parameters: PIXEL_W1..32; MAX_WIDTH/MAX_HEIGHT1..256; CAP=MAX_WIDTH*MAX_HEIGHT<=4096; CAP*PIXEL_W<=98304 bits per bank. Runtime width/height must be nonzero within maxima. Invalid static/runtime/rate parameters complete error1. The payload bound deliberately rejects32-bit4096pixels; legal32-bit maximum is3072pixels, e.g64x48. There are3CAP pixel slots plus a registered output token. This is small on-chip storage only:1080p or other large frames require a separately designed external-DDR multi-buffer controller; no such path is claimed here.

The independent Python oracle uses input-completed frame snapshots, rational reference phase and ready/valid observations, not the DUT bank/FSM implementation. It predicts every selected frame ID, pixel, marker, repeat/drop/underrun/overrun counter, including old-state priority for simultaneous publication/due/last-output-consume.
