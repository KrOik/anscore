# Seam-guided multiband frame blend

`seam_multiband_blend.sv` is a complete two-image frame pipeline: capture A/B, find an actual minimum-cost stitching seam, construct its hard/feather mask, and run actual Laplacian pyramid multiband fusion. It instantiates the frozen `seam_find` and `multiband_blend` modules unchanged. No mask, seam or intermediate image is generated by the host.

## Data path

Accepted A/B pixels are written to a 1024×16 clocked-read pair RAM while they feed the seam finder. After DP and backtracking, each generated mask pixel is held until the corresponding stored A/B pair has been fetched. The three fields transfer together into `multiband_blend`. A two-cycle RAM fetch state and ready/valid coupling prevent a mask from advancing before its image pair is available. The main test checks this actual internal transfer alignment as well as final output pixels.

The seam objective, tie rules, linear feathering and packed coordinate convention are documented in [seam_find](../seam_find/README.md). The binomial Gaussian kernel, odd-size rules, signed Q8 Laplacian arithmetic, OpenCV-compatible upsampling border and reconstruction rounding are documented in [multiband_blend](../multiband_blend/README.md). This top adds sequencing and frame replay; it does not change either numerical contract.

## Interface and configuration

Runtime width/height are **1…32**, pyramid levels **2 or 3**, gradient weight **0…255**, feather radius **0…32**, and seam direction is vertical or horizontal. Configure with `cfg_valid && cfg_ready && ce`; wait for `cfg_done` or `cfg_error`. The top prevalidates the complete configuration **before either child receives it**. An invalid level count, for example, cannot update the seam child alone; an invalid feather cannot update the blend child alone. Rejected external configuration preserves the prior working configuration.

For a valid configuration, both child commits must complete successfully before the top pulses `cfg_done` and allows START. `cfg_ready` is idle-only; configuration has priority over START. The saved configuration is independent of subsequent raw configuration input changes.

Start with `start_valid && start_ready && ce`. Supply `s_a/s_b` together in raster order, with `s_sof` only on the first pixel, `s_eol` on each row end and `s_last` only on the final pixel. Every transfer requires `ce && valid && ready`. Hold source fields until accepted. The output `m_data` is the reconstructed unsigned grayscale image, in original geometry, with `m_sof/m_eol/m_last`; output payload remains stable under CE stalls and backpressure.

`seam_coordinates[6*i+:6]`, `seam_length` and `total_cost` expose the actual selected path and its exact cost. They follow the child seam convention and are valid at successful completion. `done_valid` is asserted only after both the complete mask transfer and final blended pixel acceptance. Statistics remain stable during successful held DONE, until `ce && done_ready`. Another frame can start afterward without reconfiguration or reset. `busy` includes child configuration and automatic recovery states as well as active frames and held completion.

## Failure and reset recovery

Active-frame `abort` reports `93` hexadecimal. Seam errors report `10|seam_error`; blend errors report `20|blend_error`. Input marker errors therefore report `11`. An unexpected internal child-configuration rejection reports `94`; an invalid top state reports `95`. `done_error` identifies a failed completion. Abort during already-held successful DONE is ignored. External output validity and child output readiness are both gated by abort and terminal child errors, preventing unmatched transfers at those edges.

On any frame failure, top output validity stops and held error DONE is asserted. **Discard the entire frame**, including any output pixels already consumed before an abort. The FAILED state resets both children; its statistics are not valid image results. Held error completion is stable until an enabled DONE acknowledgement.

After error acknowledgement the top automatically replays its saved configuration into **both reset children**, waits for both commits and only then reasserts `start_ready`. The caller can START a healthy frame without manually repairing child configuration. `cfg_ready` is low during that restoration, and internal restoration does not emit an external `cfg_done` pulse.

Synchronous active-low reset overrides CE and cancels configuration, capture, seam calculation, replay, pyramid processing, output or held DONE. It invalidates top configuration; the caller must configure again. RAM is not cleared, because complete subsequent capture and child processing overwrite every address that can be consumed.

## Reproduce validation

From the repository root:

```powershell
python -B cores/system/common_scaffold/image/seam_multiband_blend/test_pipeline.py
python -B cores/system/common_scaffold/image/seam_multiband_blend/test_errors.py
python -B cores/system/common_scaffold/image/seam_multiband_blend/synth.py
```

The independent golden composes the existing numerical shortest-path/feather model with the independent integer Laplacian pyramid model, neither of which reads RTL internal results. Every actual output byte/marker, complete seam coordinate vector and total cost is checked. At every child mask transfer, the test separately verifies the synchronous replayed A/B pair and expected mask. Eight fixtures, ten actual frames, cover 1×1, thin axes, odd dimensions, full 32×32 capacity, both directions, hard/feather masks, gradient extremes, 2/3 pyramid levels, no-reset replay and an explicitly curved zero-cost seam. Actual OpenCV double-precision pyramid reconstruction differs by at most one output gray level on these fixtures.

Error tests verify partial-invalid configuration cannot commit to either child, active configuration retention, SOF/EOL/LAST errors, abort during capture/DP/replay/pyramid filtering/held output, stable error and successful DONE, CE-gated acknowledgement, and nine CE-low reset phases. Directed valid-and-ready output tests assert abort or inject a terminal child error and verify that external acceptance and child readiness are both blocked at the sampling edge. Nineteen full healthy recovery frames check all output pixels/markers/path/cost, including automatic child reconfiguration after every error acknowledgement.

Full-hierarchy `synth_gowin -noalu -nodsp; check -assert` passes: **3652 LUT1…4, 1341 FF, 1 DPB, 11 DPX9B, 24 RAM16SDP4, 0 DSP**, plus mux cells listed separately. This includes both complete numerical child engines and top replay RAM. It satisfies the isolated 15K LUT/4 DSP target. It is not a routed timing or board-validation result; processing is serial and no live-video throughput is promised. The parallel coordinate output is intended for internal integration, not direct FPGA pin assignment.

Source hashes for all three RTL files are stored consistently in numerical, error and synthesis evidence. OpenCV design references fetched for the frozen children are recorded in `reference.json`; no additional external implementation was copied. Large temporary simulation/synthesis files are automatically removed. Only compact evidence and a synthesis statistics log remain.
