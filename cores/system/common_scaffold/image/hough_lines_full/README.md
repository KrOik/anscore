# Complete polar Hough lines

`hough_lines_full.sv` is a genuine binary-edge polar accumulator and iterative global-peak detector. It is independent of the frozen four-direction implementation. No external endpoint extraction, probabilistic sampling, or line-segment claim is made.

Coordinates are raster pixel `(x,y)` with origin at the upper left. Each nonzero edge casts exactly one vote at each configured theta, with `rho = round_away_from_zero((x*cosQ14(theta)+y*sinQ14(theta))/16384)`. `trig.mem` contains actual signed sine/cosine Q14 coefficients for all 180 integer degrees, generated by `generate_tables.py`. Coordinate products use one shared shift/add datapath, six cycles per coordinate. There is no runtime trigonometric approximation or four-angle aliasing.

Legal compile-time dimensions are 1..32 on each axis. `THETA_STEP` must be a positive divisor of 180 and no larger than 90; default 1 gives the complete 180-angle transform. The accumulator has `(180/THETA_STEP)*91` unsigned 11-bit cells with signed rho bins -45..45. Every input edge is visited at every theta; every accumulator cell is cleared for each good frame. One bin can never exceed 1024 votes. Votes are raw unnormalized counts, including boundary lines; no perimeter/length normalization is applied.

Runtime START snapshots `cfg_threshold` 1..1024, `cfg_max_lines` 1..16, `cfg_theta_nms` 0..90 degrees, and `cfg_rho_nms` 0..90 pixels. The maximum remaining score is selected repeatedly. Scores must be at least the threshold. Equal scores select the lowest theta and then lowest signed rho. NMS removes the inclusive rectangle in shortest angular distance and rho distance. If raw theta separation exceeds 90 degrees, the shortest path crosses 0/180 and **the reference rho sign is reversed**: compare `abs(candidate_rho+selected_rho)`. Otherwise compare `abs(candidate_rho-selected_rho)`. Exactly 90 degrees deterministically uses the latter convention. Zero NMS radii still suppress the exact selected cell.

## Interface

All transfers require a rising edge with `ce=1`. `rst_n=0` synchronously resets control even when CE is zero; it does not reset RAM contents. START is `start_valid && start_ready`; readiness includes CE. Every accepted START clears result validity and metadata, including rejected configurations. Stream input is binary `s_edge` with valid/ready plus SOF/EOL/LAST; a frame always has exactly WIDTH*HEIGHT accepted samples. SOF is required only on the first pixel, EOL only at each row end, LAST only on the final pixel. Malformed markers consume the complete frame, return error 2, and produce **no** peak prefix. Invalid configuration returns error 1 without consuming input; illegal controller state returns error 4. Codes are enumerations, not masks.

Output `m_theta` is the normal angle in degrees; `m_rho` is signed pixels; `m_score` is the raw edge count. `m_index` is a zero-based peak index, not a count. Output and metadata remain stable while stalled or CE is low. `m_valid && m_ready && ce` accepts a peak. There is no peak-LAST bit: held `done_valid` signals that all peaks have been accepted, including the zero-peak case. Acknowledgment requires `done_ready && ce`. `busy` includes held completion. A new START is accepted only after completion acknowledgment. Result metadata after successful completion describes the last accepted peak; after any new rejected START it is zero. There is no abort port.

RAM reads are explicitly clocked; accumulator read/modify/write shares a physical address port and maps to synchronous block RAM. This implementation favors bounded area over throughput: it captures a frame, clears the accumulator, serially votes, then scans/suppresses peaks. It does not accept overlapping frames or promise a pixel per clock. `TRIG_FILE` may override the ROM path; otherwise run from this directory.

## Reproduce

From the repository root:

```powershell
python -B cores/system/common_scaffold/image/hough_lines_full/run_tests.py
python -B cores/system/common_scaffold/image/hough_lines_full/test_protocol.py
python -B cores/system/common_scaffold/image/hough_lines_full/test_invalid_parameters.py
python -B cores/system/common_scaffold/image/hough_lines_full/synth_check.py
```

The independent oracle exhaustively counts edges for every bin rather than copying the RTL edge-first accumulation schedule. Tests compare the entire pre-NMS RTL accumulator and all selected peaks, not just a digest. Actual installed scikit-image `hough_line` bins are compared; every mismatch must be attributable to a pixel within the mathematically bounded Q14 trig quantization distance of a half-integer rho boundary. Those differences are reported rather than silently accepted as exact floating parity. Actual OpenCV `HoughLines` output is recorded for every fixture, with a direct vertical-line rho/theta assertion for the theta-wrap fixture. Library peak thresholds and NMS/tie conventions differ, so their complete selected-peak lists are not claimed bit-identical.

`fetch_references.py` retrieves real upstream Hough implementations; `references.json` preserves URLs, sizes and hashes. The RTL was written independently from the documented transform. Temporary simulations, generated testbenches, synthesis scripts and large logs are confined to `TemporaryDirectory` and automatically removed, including on failure. Small JSON evidence is retained. No board testing has been performed for this isolated core.
