# JPEG block quantization and zigzag foundation

`jpeg_quant_zigzag.sv` implements real signed 8x8 coefficient quantization,
dequantization and the standard JPEG 64-position zigzag permutation. Existing
`ips_quant_int8_sym.v` is neural-network-style symmetric int8 quantization and
does not implement this table/permutation/block operation. This core does not
implement JPEG headers, DPCM, run-length coding or Huffman coding.

Forward mode accepts 64 row-major signed DCT coefficients and emits quantized
coefficients in JPEG zigzag order (0,1,8,16,9,2,...,55,62,63). Inverse mode
accepts that scan order, places each coefficient at its natural row-major
position, dequantizes and emits 64 natural-order coefficients. Quantizer tables
are always indexed in natural row-major order, never scan order. BITS=2..16.

Forward arithmetic is sign(x)*floor((abs(x)+floor(q/2))/q): nearest rounding,
ties away from zero, including the most-negative input. The exact integer
division uses one restoring divider over BITS+1 enabled cycles. Inverse
arithmetic multiplies signed x by unsigned q. Only final results saturate to
signed BITS range. `saturated` accumulates across a transform, is cleared at
the next block's last input handshake, and reset clears it. A single unsigned
8-bit quantizer table supports q=1..255 (baseline JPEG table precision).

## Atomic configuration and protocol

Reset starts **unconfigured**: s_ready is low until a legal complete table has
been committed. Write all 64 staging entries through table_valid&&table_ready,
using table_index and table_value, then commit cfg_inverse through
cfg_valid&&cfg_ready. The staging write-valid bitmap requires every index to
have been written since reset; an incomplete-table commit pulses cfg_error.
A complete table is first scanned synchronously for zeros, then copied into
active synchronous table RAM. cfg_done pulses only after the entire active
copy is complete. During those 256 enabled cycles no input/write/commit is
accepted. Zero entries reject the whole commit; the previous active table and
mode remain intact. No table write can race the scan/copy. The staging table
remains available for further edits after either a success or rejection.

Configuration/table writes are accepted only between blocks. A pending request
while a block is being captured cannot stall that block; the producer must
finish its 64 samples and drain outputs before configuration can commit.
At idle a commit has priority over table writes and both have priority over
the first input beat. These handshakes and all sample transfers require
**ce && valid && ready**. CE is a shared pipeline enable; downstream must also
obey CE. Valid/data stay stable across pauses and output backpressure.
Synchronous active-low reset overrides CE, discards pending blocks/outputs,
clears the staging-valid bitmap and requires a fresh complete table commit.
There are no SOF/EOL markers or timeout/partial-block recovery.

The coefficient block RAM is BITS*64 bits, with two 64x8 table RAMs and a
64-bit staging-valid bitmap. Reads are synchronous and memories are not reset.
Forward processing takes 64*(BITS+4) enabled cycles after the last input;
inverse takes 64*3. Output becomes valid two enabled edges later and has
II=3 enabled cycles without stalls. Capture, compute and drain do not overlap.

## Evidence

```
python -B cores/system/common_scaffold/dsp/jpeg_quant_zigzag/test_quant.py
python -B cores/system/common_scaffold/dsp/jpeg_quant_zigzag/test_pipeline.py
python -B cores/system/common_scaffold/dsp/jpeg_quant_zigzag/synth.py
```

The independent literal standard scan sequence checks every index, while the
RTL case table was independently generated by anti-diagonal traversal. Integer
oracles cover identity tables, random tables/coefficients, signed extremes,
ties, inverse saturation, incomplete table rejection, zero-table rejection
with opposite requested mode and retained active-table replay, CE/valid/ready
stalls, stalled payload stability, reset and terminal idle. Three bit depths
(8/12/16) exercise 30 blocks/1920 outputs.

The actual four-core RTL pipeline DCT→quant+zigzag→dequant+inversezigzag→IDCT
also passes 64 numerical outputs against the independent mathematical chain,
without changing either existing DCT module. Its random low-amplitude fixture
has maximum lossy reconstructed error 6 LSB. This is bounded functional
evidence, not a codec compliance or image quality claim.

Isolated BITS16 Gowin synthesis (`-noalu -nodsp`) reports 897 LUT1-4,
107 MUX2_LUT5, 4 MUX2_LUT6, 207 FF, 32 RAM16SDP4 and zero DSP; CHECK reports
zero problems. The multiplier is implemented in logic in this verified flow,
satisfying the <=4 DSP bound. No P&R, clock-rate or board evidence is claimed.
Temporary binaries are automatically removed; logs and small JSON evidence stay.
