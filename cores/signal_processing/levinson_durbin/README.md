# Fixed-point Levinson-Durbin LPC coefficients

`levinson_durbin` converts an autocorrelation sequence `r[0..ORDER]` into
linear prediction coefficients. The result is the final coefficient vector
`a[1..ORDER]` and one reflection coefficient for every recursion stage. It is
a reusable small-order analysis core for prediction/whitening filters. Existing
FIR/LMS modules consume or adapt coefficients; this core estimates an
autoregressive predictor from supplied autocorrelations. It does not capture
samples, calculate autocorrelation, filter a signal, or implement speech coding.

The predictor convention is `x[n] + sum(a[j]*x[n-j]) = prediction_error`.
In exact real arithmetic this corresponds to the symmetric Toeplitz system
`sum(r[abs(i-j)]*a[j]) = -r[i]` for i,j=1..ORDER. The RTL implements the
explicit fixed-point recursion below, rather than promising bit equality to
an unquantized linear solve.

## Numerical contract

Input autocorrelations are signed `DATA_W`-bit integers in any common scale.
No physical acquisition scale or fixed fractional interpretation is assumed.
Both predictor and reflection coefficients have `FRAC` fractional bits. The
coefficient port width is `COEFF_W=FRAC+ORDER+2`; reflection width is FRAC+1.
Energy has `EW=DATA_W+FRAC+1` unsigned bits and represents an input-correlation
unit scaled by `2^FRAC`. There is no implicit initial coefficient a[0] token:
its mathematical value is 1.

Let `S=2^FRAC`, `tz(n/d)` truncate a signed rational toward zero, and `a` denote
integer coefficient codes. Initially E=r[0]*S and a is empty. Stage m does:

```text
R = r[m]*S + sum(a[j]*r[m-j], j=1..m-1)
k[m] = tz(-R*S / E)
new_a[j] = a[j] + tz(k[m]*a[m-j] / S), j=1..m-1
new_a[m] = k[m]
E = E - floor(E*k[m]*k[m] / S^2)
a = new_a
```

All right-hand coefficients in one stage use the previous stage's vector.
Their updates are committed only after every new value has been calculated.
The energy product E*k*k is kept exact until the single division by S^2.
Coefficient-product truncation is toward zero also for negative products;
it is not an arithmetic-shift floor rule. No other arithmetic is rounded.

The final tokens pair `m_a=a[index]` from the final vector with
`m_reflection=k[index]` from that stage's history. These are different
quantities after stages modify earlier coefficients. `m_index` is **1-based**.
`m_energy` repeats the final E on every token. This distinction matters when
feeding final LPC coefficients to a direct-form FIR versus reflection
coefficients to a lattice filter.

`m_error` describes the entire block:

| Value | Meaning |
| --- | --- |
| 0 | All fixed-point recursion stages completed with abs(k)<S. |
| 1 | r[0]<=0; no recursion was started. |
| 2 | A stage's quantized reflection has abs(k)>=S; computation stopped. |
| 3 | Reserved, never generated by the current design. |

Every block, including an error block, emits exactly ORDER tokens in index
order. On error, **all** coefficient/reflection/energy payloads are zero,
the error and first-input tag repeat, and the final token carries m_last.
No partial-stage state is delivered as a valid predictor. There is no
saturation, silent wraparound or separate overflow flag for legal parameters.

Positive-definite autocorrelation data at adequate precision are the intended
input. Finite precision can change the inferred model and the failure point,
especially for ill-conditioned sequences or small FRAC. Error=0 certifies
completion of this defined fixed-point recursion, not positive definiteness
of the exact input Toeplitz matrix or a universal approximation-error bound.
It also does not prove filter accuracy for an unobserved future signal.

| Parameter | Default | Legal range |
| --- | ---: | --- |
| DATA_W | 16 | 2..24 |
| FRAC | 16 | 1..20 |
| ORDER | 4 | 1..8 |
| TAG_W | 8 | 1..32 |

Derived localparams describe internal widths and must not be overridden.
Invalid public parameters fail elaboration through a deliberately unresolved
parameter-error instance. The legal production design has no such instance.

## Interface, reset and ordering

Every signal uses one rising-edge clk. Reset rst is synchronous active high,
overrides work, and must span a rising edge. It cancels partially loaded
correlations, arithmetic, and pending coefficient tokens. Ready and valid
are suppressed while rst is asserted. Control and energy reset; small data
arrays and arithmetic scratch registers are initialized by their loading or
setup states before consumption. No reset memory-image file is needed.

There is no CE or CDC. Input and output transfers use ordinary valid&&ready
semantics. A producer holds s_valid, s_r and s_tag stable until acceptance.
Exactly ORDER+1 accepted words form a block, ordered r[0],r[1],...,r[ORDER].
The first accepted word's tag is retained and later tags are ignored. There
is no input last marker or runtime configuration channel; parameters take
effect at elaboration. Missing input words pause loading indefinitely;
misordered or extra words cannot be inferred from the unmarked values.
Reset is the means to restore alignment after a source framing error.

The input is ready on each loading cycle and then backpressures the producer
throughout computation/output. Blocks do not overlap. Output tokens transfer
on m_valid&&m_ready; m_a, m_reflection, m_index, m_last, m_energy, m_error and
m_tag remain stable under backpressure. There is no gap between tokens when
the sink is ready. The next block can start on the edge after the final token
transfers. No external memory/bus interface, address protocol or bus-error
response exists. Sidebands are meaningful only while m_valid is high.

`example/lpc4_example.sv` is a complete minimal default instantiation with
five signed16 correlation inputs and four signed22 Q16 predictor outputs.
It also exposes signed17 Q16 reflection values and their index/error/last.
Its standard ready/valid ends must honor the block contract above; attaching
a CE-qualified legacy source requires an appropriate semantic adapter.

## Architecture and width review

One explicitly shared iterative signed-magnitude multiplier serves residual
products, coefficient updates, and both energy products. One restoring divider
calculates reflection coefficients. There is no wide hardware multiply/divide
operator or unrolled recursion network. Small bounded arrays hold r, old/new
coefficients and reflection history; with ORDER<=8, register storage and
combinational indexed reads are intentional. BRAM inference is not assumed.
Old/new coefficient banks prevent in-place updates from changing a later
right-hand operand in the same stage.

Each successful stage satisfies abs(k)<S. The triangle inequality then bounds
the coefficient 1-norm by less than 2^stage*S; coefficient truncation cannot
increase an update's magnitude. COEFF_W provides a further signed guard bit
beyond the ORDER-dependent bound. Residual accumulation uses
`ACW=DATA_W+COEFF_W+clog2(ORDER+1)+2`, sufficient for every partial sum.
The divider uses DW=ACW+FRAC bits, so the full residual is widened before
scaling. No high quotient bits are discarded before the abs(k)<S check.

The multiplier operand width is
`MW=max(DATA_W+2*FRAC+3,COEFF_W+1)`, including the full E*k intermediate used
as the second energy multiplication's input. Products retain 2*MW magnitude
bits plus an explicit sign. E is positive and nonincreasing on successful
stages: because k^2<S^2, floor(E*k^2/S^2)<=E-1, so E cannot become zero and
the divider never starts with zero energy. These are arithmetic invariants,
not measured synthesis properties.

Qualitative architecture risk is **MEDIUM**, including maximum parameters.
Register arrays grow as ORDER*(DATA_W+FRAC+ORDER); state and arithmetic also
grow with DATA_W/FRAC. The default shared multiplier has 51-bit operands,
102-bit magnitude accumulation, a 59-bit dividend and a 44-bit remainder
comparison domain. Wide iterative adds/subtracts are expected critical paths.
There is no external RAM, vendor primitive, hard IP or mandatory DSP block.
LUT/FF/DSP count, BRAM mapping, frequency, power and device fit are unmeasured.

Per successful stage m, the controller takes
`2*m*(MW+2)+DW+m+4` clocks. After the final correlation is accepted, a
successful block therefore raises output-valid after
`1+(MW+2)*ORDER*(ORDER+1)+ORDER*DW+ORDER*(ORDER+1)/2+4*ORDER`
clock periods (1323 by default). A bad r[0] block raises valid after one
period; reflection failure exits at its failed stage's divide completion.
Earliest output acceptance is one edge after valid rises. Later ready tokens
can transfer every cycle. Source gaps and sink stalls extend total completion
time. These are source-level schedules, not hardware throughput measurements.

## Offline package and finite evidence

files.f lists the sole production RTL file. There are no includes, ROMs,
generated tables, external arithmetic cores or downloadable runtime assets.
The example and deterministic testbench generator are local source.
All code is original Apache-2.0; SOURCES.md records fixed upstream reference
revisions and actual licenses. The package .gitattributes fixes LF text to
keep source SHA256 and eventual Git blobs consistent.

From this directory, source compilation is:

```text
iverilog -g2012 -Wall -tnull -s levinson_durbin -f files.f
```

From the repository root, run the finite suite:

```text
python -B cores/signal_processing/levinson_durbin/run_tests.py
```

The runner requires Python 3 standard library and Icarus/vvp. It prefers the
existing local OSS CAD Suite and prepends bin/lib to subprocess PATH. Every
process is limited to 15 seconds. Testbench text and simulator executables
use a task-specific temporary directory removed on exit; the full TB template
and fixtures remain in run_tests.py. Failed reruns remove stale PASS evidence.
LF violations are rejected before running tools.

Six profiles cover DATA_W/FRAC/ORDER/TAG_W:
2/1/1/1, 8/4/2/3, 16/16/4/8, 24/20/8/32, 8/1/8/8 and 2/1/8/2.
They include minimum/maximum widths/orders, white correlation, signed AR-like
correlation, exactly representable +/-0.5 AR(1) cases where the input range
allows them, zero/negative r[0], unstable first/later reflections, signed
extremes, sample-derived positive autocorrelations, and seeded arbitrary input.
The 2/1/8 profile exercises the COEFF_W-dependent multiplier-width branch.

The exact acceptance oracle uses high-level Python lists, unbounded integer
products and the specified truncation points. It shares no RTL state/address
schedule. A separate Fraction Gaussian elimination of the unquantized
Toeplitz system reports observed coefficient differences for successful
fixtures; that comparison is descriptive and never a tolerance used to hide
an RTL mismatch. The defined fixed-point outputs must match exactly.
Protocol checks cover input gaps/blocked data, tag capture, index/last/error,
first-token output stalls, reset during input/multiply/divide/stalled output,
and reuse without reset. Eight illegal parameter cases and default/example
compilation are checked. This is finite unit coverage, not an arbitrary-input
or all-parameter proof.

Actual commands, outputs, profile counts, tool version and package SHA256 are
in verification.json. Current maturity: **LINT_PASS + UNIT_SIM_PASS**;
the example is an **INTEGRATION_CANDIDATE**, and all code is
**HW_UNVERIFIED**. No synthesis, PnR, STA, hardware testing or full regression
was performed, and no previous hardware evidence is attributed to this RTL.
