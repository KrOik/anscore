## 2. 通用 P&R 审计工具 `tools/pnr_audit.py`

裸核直接送 nextpnr 会因无约束 IO 报错(`Unconstrained IO:tap_re[9]...`),且 `synth_gowin` 会 flatten 导致 DUT 计数为 0。方案:

1. `dump_ports`:读 RTL 顶层端口表;
2. `gen_wrapper`:生成 `pnr_top` 寄存器壳(LFSR 激励输入、寄存器捕获输出、`obs` 异或观察),约束 `clk=H11, rst_n=T13, obs=M11`;
3. 两次 `synth_gowin -noalu -family gw2a`:包装壳(产出 `mapped.json` 送 P&R)+ 独立 DUT pass(精确计数);DUT pass 失败时以 wrapper 作为资源上界(`resource_source=wrapper_upper_bound`);
4. `nextpnr-himbaechel --device GW2A-LV18PG256C8/I7 --vopt family=GW2A-18 --vopt cst=top.cst --freq 27 --seed 1`;
5. 门槛:LUT1-4+ALU ≤15000,DSP(MULT/PADD/ALU54)≤4,min Fmax ≥27MHz;逐用例落盘 `summary.json` + 全部日志。

### 审计结果:56/61 用例 PASS(5 FAIL 均为真实物理约束违例)

| 用例 | 结果 | 原因 |
|---|---|---|
| DSP-14 stft_welch RAM_REGS=1 | FAIL | 5 DSP(>4 门限),且 nextpnr 无法合法布局(12173 LUT4, 58%) |
| ISP-06 scale_poly6 MAX_W=1920 | FAIL | 需 141 BSRAM,GW2A-18 仅 46(306% 超额) |
| ISP-06 scale_poly6 MAX_W=64 | FAIL_GATE | 54 DSP ≫ 4(并行 Lanczos MAC 结构) |

其余 56 用例全部过 ≤15K LUT / ≤4 DSP / ≥27MHz 门限,含修复依赖后的 ddc_cic3(5105 LUT/4 DSP/67.17MHz)、stft 依赖补全后暴露真实约束超限、PFB 包装路径 7335 LUT4/4 DSP/121.23MHz(DUT 独立计数被跳过,记录 wrapper_upper_bound)。
