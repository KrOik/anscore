# scale_poly6_stream — 36-point polyphase video scaler

Separable 6-tap x 6-tap (36 source pixels per output pixel) Lanczos-3
polyphase scaler for RGB888 raster streams on Tang Primer 20K (GW2A-LV18).

## Interface

Stream contract follows `infra/stream/README.md`: single `clk`, synchronous
active-low `rst_n`, `s_`/`m_` `tdata/tvalid/tready`, `tuser[0]=SOF`,
`tlast=EOL`. `tdata[23:0]` is `{R,G,B}` 8-bit per channel.

Runtime configuration (dimensions only):

| Signal | Dir | Meaning |
|---|---|---|
| `cfg_valid`/`cfg_ready` | in/out | handshake; accepted only between frames (`!busy`, divider idle) |
| `cfg_in_w/cfg_in_h` | in | input frame dims, 1..MAX_W / 1..4095 |
| `cfg_out_w/cfg_out_h` | in | output frame dims, 1..MAX_W / 1..4095 |
| `cfg_done` | out | one-cycle pulse when Q16.16 steps are ready (~56 cycles after fire) |
| `cfg_error` | out | latched on zero/out-of-range dims or step > 64.0; clears on next `cfg_valid` |
| `marker_error` | out | latched on SOF/EOL protocol violation |
| `busy` | out | high from input SOF until the last output beat is consumed |

## Algorithm

Per output pixel at fractional source center `c`:

- `step = round(in*65536/out)` (Q16.16, on-chip 28-iteration divider per axis)
- `c(0) = (step - 65536)/2` (arithmetic shift, signed), `c(n+1) = c(n) + step`
- taps at `floor(c)-2 .. floor(c)+3`, clamped (edge replication) to
  `[0, in-1]`; phase index = `frac(c) >> 10` (64 phases)
- coefficients: Lanczos-3, signed Q1.11 in a 13-bit container, per-phase sum
  forced to exactly 2048 (`scale_lanczos3.vh`, generated by
  `gen_scale_coeffs.py`)
- vertical MAC: `clamp((sum(p8*c13) + 64) >> 7, 0, 4095)` -> 12-bit/channel
  intermediate row (4 fractional bits kept between stages)
- horizontal MAC: `clamp((sum(p12*c13) + 16384) >> 15, 0, 255)`

`scale_model.py` is bit-exact for this pipeline.

## Structure

- 7 line banks (`MAX_W` x 24-bit each, BSRAM): input row `r` resides in bank
  `r%7`. A vertical sweep reads the 6 banks covering its tap rows; the
  remaining residue `(L+6)%7` is provably free, so the next input row keeps
  streaming during a sweep (`over_in`).
- Vertical sweep: one intermediate pixel/cycle, `in_w + 2` cycles per output
  row, into ping-pong intermediate buffers `ib0/ib1` (`MAX_W` x 36-bit).
- Horizontal stage: sliding 6-pixel window over the intermediate row; emits
  up to 1 pixel/cycle (II=1 when the phase step advances the window by <=1);
  out-of-window shifts take one cycle each. Writes ping-pong output buffers
  `ob0/ob1` (`MAX_W` x 24-bit).
- Drain stage re-marks `tuser`/`tlast`; full backpressure chain
  `m_tready -> drain -> hstage -> vstage -> s_tready`.

## Limits

- Fixed 6-tap kernel: clean for upscaling and mild downscaling; downscale
  ratios beyond ~2x alias increasingly (the kernel support does not widen).
  Steps up to 64.0 are accepted; quality at large ratios is the caller's
  responsibility — that is a deliberate scope cut, not a silent bug.
- `in_w`, `out_w <= MAX_W` (1920 default); heights up to 4095.
- Output rate is internally timed, not sync-locked: average throughput is
  ~max(in_w, out_w) cycles per output row plus input dwell time.

## Verification

```
python cores/signal_processing/dsp_isp_library/isp/scale/test_scale.py
```

13 configurations x 3 stall profiles (0%, 40/30%, 70/60% random input gaps /
output stalls): identity, 2x/1.5x/3x upscale, 1.5x/4x downscale, non-integer
ratios, tiny frames (down to 1x1 input), asymmetric scales, and multi-frame
sequences with per-frame reconfiguration. A checker-mutation run
(`mutant_expect_fail`) proves a corrupted expected beat is reported. All
beats compared bit-exact against `scale_model.py`; evidence under
`isp/scale/evidence/sim_*/` (input/expected mems, logs, summary.json,
source hashes).

## Synthesis (yosys synth_gowin, MAX_W=1920)

- DSP mapped (`synth_gowin -noalu`): ~6.8K LUT-class + 18 MULT18X18 +
  36 MULT9X9 (~36 DSP18 slots). Fits the 15K LUT budget; the 36 parallel
  MACs are the whole point of the 36-tap architecture but exceed the repo's
  4-DSP shared-image budget — use `-nodsp`, smaller MAX_W, or a
  time-multiplexed variant when budgeting a shared image.
- All-LUT (`synth_gowin -noalu -nodsp`): ~17.0K LUT-class — over the 15K
  budget at MAX_W=1920; halving MAX_W barely helps (multiplier cost is
  resolution-independent). Prefer DSP mapping for this core.
- BSRAM payload: 7x1920x24 (line banks) + 2x1920x36 (intermediate) +
  2x1920x24 (output) = ~552 Kbit; GW2A-18 BSRAM capacity is 828 Kbit.
- DRC: `Found and reported 0 problems` in both variants.
